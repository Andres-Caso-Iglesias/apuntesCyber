**Diccionarios: cuál usar y para qué**

Antes de entrar en los servicios, la clase aclara un punto práctico que genera dudas frecuentes: qué diccionario usar en cada situación.

Los diccionarios se guardan por defecto en /usr/share/wordlists/. Los más relevantes son:

- **RockYou:** el clásico para romper hashes y fuerza bruta de contraseñas. Ideal para CTFs y certificaciones. En entornos reales funciona bien para contraseñas débiles o antiguas
    
- **SecLists:** la colección más completa disponible. Tiene subdirectorios para fuzzing web, usuarios, contraseñas, payloads de SQL Injection, LFI y mucho más. Se descarga con git clone desde su repositorio de GitHub. Pesa bastante pero merece la pena tenerlo
    
- **Caonasi:** más reciente, actualizado con contribuciones de la comunidad, buena opción como complemento
    
- **DirBuster (medium):** el que se usó en clase para fuzzing de directorios. El diccionario medium es el punto de equilibrio entre velocidad y cobertura
    

Para fuzzing de directorios, SecLists y DirBuster medium son la referencia. Para romper hashes, RockYou. Para usuarios en ataques de fuerza bruta, SecLists tiene listas específicas.

**Puerto 25 — SMTP: enumeración de usuarios**

SMTP (Simple Mail Transfer Protocol) es el protocolo de envío de correo. Su relevancia en una auditoría no es enviar correos, sino que permite enumerar qué usuarios existen en el sistema usando dos comandos nativos del protocolo: EHLO (saludo inicial entre cliente y servidor) y VRFY (verificar si un usuario existe).

Metasploit tiene un módulo escáner específico:

```
search smtp_enum
use 0
set RHOSTS IP_OBJETIVO
run
```

El módulo prueba automáticamente estos comandos contra un diccionario de usuarios y devuelve los que existen en el sistema. El resultado en esta máquina incluye usuarios como backup, bin, daemon, ftp, games, www-data y user.

El usuario www-data merece atención especial: es la cuenta de servicio del servidor web. En Linux, cada servicio importante corre bajo su propio usuario con permisos mínimos. Si se compromete el servicio web, el acceso inicial será como www-data, no como root. Desde ahí hay que escalar. Esta jerarquía — cuenta de servicio → usuario local → root — es el esquema de escalada que se repite constantemente.

Los usuarios enumerados se guardan en un fichero .txt para usarlos después en ataques de fuerza bruta.

- **La idea clave:** SMTP no sirve para hackear directamente, sirve para construir el diccionario de usuarios del sistema. Ese diccionario luego se combina con ataques a otros servicios

**Puertos 512, 513, 514 — Servicios R: acceso sin autenticación**

Los servicios rlogin, rsh y rexec son protocolos de acceso remoto de los años 80, anteriores a SSH. Están completamente obsoletos y no cifran nada. Su vector de ataque es directo: existe un fichero llamado .rhosts que contiene las IPs autorizadas a conectarse. Si ese fichero está mal configurado con un comodín que permite cualquier IP, cualquiera puede conectarse sin contraseña.

```
rlogin -l root IP_OBJETIVO
```

En Metasploitable 2, el fichero .rhosts acepta todas las IPs, por lo que este comando entra directamente como root. Es un ejemplo extremo de mala configuración, prácticamente imposible de ver en entornos reales modernos, pero que sigue apareciendo en CTFs y certificaciones.

- **La idea clave:** estos servicios no se explotan por una vulnerabilidad del software sino por una mala configuración del sistema. La diferencia importa: una versión desactualizada se parchea, pero una mala configuración requiere que alguien la revise y corrija manualmente

**Puerto 2049 — NFS: montar el sistema de ficheros completo**

NFS (Network File System) es el equivalente Linux de las carpetas compartidas de SMB. Es muy habitual encontrarlo en entornos reales y en certificaciones. El problema no es tener NFS abierto, sino qué está compartiendo.

El flujo de ataque es:

```
rpcinfo -p IP_OBJETIVO          # Confirmar que NFS está activo
showmount -e IP_OBJETIVO        # Ver qué está compartido
```

En este caso, el resultado de showmount muestra / con acceso para *, es decir, el directorio raíz del sistema completo compartido para cualquier IP. Esto es excepcional y catastrófico, aunque sí ocurre en la práctica con administradores descuidados.

```
mkdir /home/kali/Desktop/carpeta_meta2
sudo mount -t nfs IP_OBJETIVO:/ /home/kali/Desktop/carpeta_meta2
```

Con esto, el sistema de ficheros completo de Metasploitable 2 queda montado localmente. A partir de ahí se puede navegar como si fuera el propio sistema.

**Qué se puede hacer con acceso al sistema de ficheros completo:**

El fichero /etc/shadow contiene los hashes de todas las contraseñas del sistema. Cada línea tiene el formato:

```
usuario:$tipo$hash:politicas_contraseña
```

El prefijo del hash indica el algoritmo: $1$ es MD5, $5$ es SHA-256, $6$ es SHA-512. Las cuentas con * o ! al inicio del hash están deshabilitadas.

También se pueden explorar los directorios home de los usuarios buscando claves SSH:

```
ls -la /home/msfadmin/.ssh/
```

**Rompiendo hashes: John the Ripper y Hashcat**

Con los hashes del shadow guardados en un fichero, se lanzan dos herramientas:

**John the Ripper:**

```
john --format=md5crypt --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
john --show hashes.txt    # Ver los hashes ya rotos (se guardan en base de datos interna)
```

**Hashcat:**

La referencia para identificar el modo correcto es la documentación oficial de Hashcat, que lista todos los tipos de hash con ejemplos. Para MD5crypt el modo es 500:

```
hashcat -m 500 hashes.txt /usr/share/wordlists/rockyou.txt
hashcat -m 500 hashes.txt /usr/share/wordlists/rockyou.txt --status    # Ver progreso
```

Hashcat aprovecha la GPU para acelerar el proceso. En entornos profesionales se montan servidores con múltiples GPUs dedicadas a esta tarea. La diferencia de velocidad entre CPU (John) y GPU (Hashcat) es de varios órdenes de magnitud.

Si se usan los mismos diccionarios, ambas herramientas deben obtener los mismos resultados. La ventaja de Hashcat es que permite aplicar reglas adicionales: que la contraseña empiece por mayúscula, que termine en números, que siga patrones de fecha, etc. Esto la hace más potente para contraseñas que no están en el diccionario en su forma exacta.

- **La metáfora útil:** el diccionario es la munición, la herramienta es el arma. Con la misma munición, una pistola y un rifle hacen el mismo daño — la diferencia es la velocidad y la capacidad de afinar la puntería

**Robando y plantando claves SSH a través de NFS**

Tener acceso al sistema de ficheros completo permite interactuar con las claves SSH como si fuéramos el administrador del sistema. Esto abre dos vectores:

**Vector 1 — Robar la clave privada existente**

En /home/msfadmin/.ssh/ existe un par de claves. La clave pública que aparece en authorized_keys del usuario root es la misma que la del usuario msfadmin. Esto significa que con la clave privada de msfadmin se puede conectar como root:

```
chmod 600 id_rsa
ssh -i id_rsa root@IP_OBJETIVO
```

**Vector 2 — Generar una clave nueva y plantarla (persistencia)**

Más interesante para persistencia: generar un par de claves propio y añadir la pública al authorized_keys de root. Como la carpeta compartida está montada en tiempo real, lo que se escribe en local se escribe en el sistema remoto:

```
ssh-keygen -t rsa    # Sin contraseña para la clave
cat id_rsa.pub >> /ruta/montaje/root/.ssh/authorized_keys    # >> añade, no sobreescribe
chmod 600 id_rsa
ssh -i id_rsa root@IP_OBJETIVO
```

Con esto se establece persistencia: aunque alguien revise el sistema y cambie contraseñas, la clave plantada sigue funcionando porque está en authorized_keys. Es una de las técnicas de persistencia más silenciosas y efectivas en Linux.

- **La idea clave:** NFS con la raíz compartida no es solo un vector de lectura. Es escritura en tiempo real sobre el sistema remoto. La distinción entre "montar" y "copiar" es crucial: los cambios se aplican directamente en el objetivo

**Puerto 5900 — VNC: escritorio remoto por fuerza bruta**

VNC (Virtual Network Computing) permite acceso a escritorio remoto gráfico. La enumeración con Nmap ya detecta la versión. El ataque es fuerza bruta con Hydra:

```
hydra -P /usr/share/wordlists/rockyou.txt vnc://IP_OBJETIVO
```

Hydra encuentra la contraseña. Con ella, vncviewer o un cliente equivalente da acceso al escritorio gráfico de la máquina víctima directamente.

**Puerto 80 — Hacking web: fuzzing, robots.txt y fuerza bruta**

La clase cierra con el inicio del módulo web, que se desarrollará en profundidad las próximas semanas.

**Fuzzing con FFUF y alternativas**

Como vimos en la clase anterior, FFUF permite descubrir directorios ocultos. La sintaxis básica:

```
ffuf -u http://IP_OBJETIVO/FUZZ -w /usr/share/dirbuster/wordlists/directory-list-2.3-medium.txt -c
```

El marcador FUZZ se sustituye por cada entrada del diccionario. Si se mueve al principio de la URL, busca subdominios en lugar de subdirectorios. Alternativas: DirBuster (con módulo en Metasploit: search dir_scanner), Gobuster y Feroxbuster. Todas hacen básicamente lo mismo; la diferencia está en velocidad, output y opciones de configuración.

**robots.txt: el mapa de lo que quieren ocultar**

Siempre revisar [http://IP/robots.txt](http://ip/robots.txt). Es el fichero que indica a los motores de búsqueda qué no indexar. Todo lo que aparece como Disallow existe precisamente porque no quieren que se vea. En la máquina de clase aparece una entrada que apunta a un directorio con un fichero de cuentas con usuarios y contraseñas en texto claro, y otro con la configuración de conexión a base de datos incluyendo credenciales.

**Herramientas de fingerprinting web**

Dos extensiones de navegador útiles para identificar tecnologías: **Wappalyzer** detecta el stack tecnológico (versión de PHP, servidor web, CMS, frameworks). **FoxyProxy** gestiona la configuración del proxy para Burp Suite.

**Fuerza bruta en formularios con Hydra**

Para atacar un formulario de login por POST:

```
hydra -l admin -P /usr/share/wordlists/rockyou.txt IP_OBJETIVO http-post-form "/login.php:username=^USER^&password=^PASS^&login=login:Login failed"
```

Los parámetros del formulario se obtienen inspeccionando el código fuente de la página (los atributos name de los campos input). La cadena al final es el mensaje que aparece cuando el login falla, para que Hydra sepa distinguir éxito de fracaso. El resultado en clase: admin / password.

**Introducción a Burp Suite**

Burp Suite es el proxy estándar de la industria para hacking web. Se configura en el navegador apuntando al 127.0.0.1:8080, y desde ese momento todas las peticiones HTTP pasan por Burp antes de llegar al servidor. Esto permite:

- Ver exactamente qué se está enviando (campos de formulario, cabeceras, cookies)
    
- Modificar cualquier parte de la petición antes de enviarla
    
- Repetir peticiones modificadas sin recargar el navegador
    
- Automatizar ataques de fuerza bruta con el módulo Intruder
    

Un caso práctico directo: si una web valida en JavaScript que el teléfono solo acepta números, Burp permite interceptar la petición POST y cambiar el número por un nombre de usuario, porque la validación del front-end no existe en el back-end. Esto se verá en profundidad en las próximas sesiones.
