**El mapa mental de la escalada de privilegios**

Antes de continuar con la máquina, Carlos dibuja en pizarra el esquema conceptual que vertebra toda la fase post-explotación. Es el marco más importante de la sesión.

Dentro de un sistema comprometido hay tres tipos de cuentas:

- **Cuentas de servicio:** asociadas a un servicio concreto (FTP, Apache, PostgreSQL). Tienen permisos muy reducidos sobre el sistema pero amplios sobre su propio servicio. No tienen directorio en /home. Cuando comprometemos una página web y hacemos whoami, el resultado típico es www-data
    
- **Cuentas de usuario:** tienen directorio propio en /home, pueden ejecutar comandos del sistema, leer y escribir en su espacio. Son el objetivo del movimiento lateral
    
- **Root:** el administrador del sistema. El objetivo final de la escalada de privilegios
    

El flujo completo de un pentest interno sigue siempre este esquema:

```
Cuenta de servicio → Cuenta de usuario → (otras cuentas de usuario) → Root
```

Cada salto entre cuentas se llama **movimiento lateral**. Puede haber tantos saltos como sean necesarios, usando los permisos de una cuenta para acceder a recursos de la siguiente. La **escalada de privilegios** es el salto final hasta root.

- **La idea clave:** comprometer un sistema no significa ser root automáticamente. Lo normal es entrar como una cuenta de servicio y tener que navegar lateralmente por los usuarios del sistema hasta encontrar el camino hacia root. Entender qué puede hacer cada cuenta es la base de todo esto

**Movimiento lateral — Summer → Rick Sánchez → Morty**

Conectados por SSH en el puerto 22222 como el usuario summer con contraseña winter, el primer paso es siempre el mismo reconocimiento interno:

```
sudo -l        # Listar comandos ejecutables como sudo
uname -a       # Versión del sistema operativo
id             # Ver grupos y permisos del usuario actual
```

El fichero /etc/passwd revela los usuarios del sistema. Los que tienen /bin/bash o /bin/sh al final son usuarios reales con shell. Los que tienen /nologin o /false son cuentas de servicio. En esta máquina aparecen rick, morty y summer como usuarios reales.

**Permisos de ficheros: la regla lectura-escritura**

Para copiar un fichero se necesitan exactamente dos permisos: lectura en el origen y escritura en el destino. No hace falta más. Esto es fundamental para entender por qué la carpeta /tmp es tan usada:

```
ls -la /tmp
```

/tmp tiene el bit especial t (sticky bit) y permisos de lectura, escritura y ejecución para todos los usuarios. Por eso es donde se deposita código malicioso cuando no se tiene un directorio propio con permisos de escritura.

Navegando a /home/rick se encuentran dos ficheros: safe (ejecutable) y journal.txt. Para copiarlos al directorio de trabajo:

```
cp safe ../../home/summer/safe
cp journal.txt ../../home/summer/journal.txt
```

Para transferir ficheros entre máquinas se usa **SCP** (SSH Copy), que es exactamente como cp pero a través de la red usando el protocolo SSH:

```
scp -P 22222 summer@10.0.2.15:/home/summer/safe ./Desktop/
scp -P 22222 summer@10.0.2.15:/home/summer/safepass.jpg ./Desktop/
```

La -P mayúscula especifica el puerto (diferente a SSH donde es minúscula). El formato es siempre usuario@IP:/ruta/origen destino_local.

En la carpeta de Morty hay un ZIP protegido con contraseña y una imagen safepass.jpg. El comando strings extrae cadenas de texto legibles de cualquier fichero binario, incluyendo imágenes:

```
strings safepass.jpg
```

Dentro de la imagen, oculta mediante esteganografía, aparece la cadena MISIC. Esta es la contraseña del ZIP. Al descomprimirlo aparece un fichero de texto con una pista: la contraseña de Rick sigue una política concreta: una mayúscula, un dígito, y una palabra del nombre de su antigua banda, **The Crimpson Court**.

**Generación de diccionario y fuerza bruta con Hydra**

Con la política de contraseñas conocida, se genera un diccionario con todas las combinaciones posibles usando IA (Claude en este caso), que produce 780 variantes. Se guarda en un fichero y se lanza Hydra contra el SSH:

```
hydra -l "Rick Sanchez" -P diccionario.txt ssh://10.0.2.15 -s 22222
```

Hydra encuentra la contraseña. La sintaxis de Hydra sigue siempre la misma lógica: -l para un usuario concreto, -L para un fichero de usuarios, -p para una contraseña, -P para un diccionario. Después el servicio y la IP, y -s para especificar un puerto no estándar.

**Escalada de privilegios final — Rick → Root**

Conectados como Rick, el sudo -l devuelve lo más valioso posible:

```
User rick may run the following commands on localhost:
    (ALL) ALL
```

ALL ALL significa que Rick puede ejecutar cualquier comando como root sin necesidad de conocer la contraseña de root. Esto permite el salto final:

```
sudo su
whoami   # root
cat /root/flag.txt
```

- **La idea clave:** sudo -l es uno de los primeros comandos que se lanza siempre al comprometer una cuenta. Si devuelve ALL ALL, el juego ha terminado. Si no, hay que seguir buscando otros vectores de escalada

**Máquina Mr. Robot — Enumeración de usuarios con Burp Suite Intruder**

La máquina Mr. Robot expone un WordPress en el puerto 80. El reconocimiento inicial sigue la metodología habitual: robots.txt revela dos ficheros, uno de ellos con la primera flag y otro con un diccionario de contraseñas.

**Sanitización del diccionario**

El diccionario tiene 856.000 líneas con muchas repeticiones. Antes de cualquier fuerza bruta, siempre se sanitiza:

```
sort diccionario.txt | uniq > diccionario_clean.txt
wc -l diccionario_clean.txt
```

sort ordena las líneas y uniq elimina duplicados consecutivos. El resultado: de 856.000 a 11.452 líneas únicas. Los tiempos de ataque se reducen 80 veces.

**Enumeración de usuarios con Burp Suite Intruder**

WordPress, en sus versiones sin parchear, revela si un usuario existe o no a través del mensaje de error del login: si el usuario no existe dice "invalid username", si existe dice "the password you entered is incorrect". Esta fuga de información se llama **information disclosure**.

Con Burp Suite activado y FoxyProxy apuntando a él, se intercepta la petición POST del login. Se envía al Intruder, se marca el parámetro del nombre de usuario como payload, y se carga un diccionario de nombres de usuario. El Intruder lanza todas las combinaciones y compara las longitudes de respuesta: cuando la longitud difiere del resto, significa que el mensaje de error es diferente, lo que confirma que el usuario existe.

El usuario elliot (protagonista de la serie Mr. Robot) devuelve una longitud diferente. Confirmado el usuario, se repite el proceso cambiando el payload a la contraseña con el diccionario limpio, hasta encontrar la combinación correcta.

- **La metáfora útil:** usar los mensajes de error de un login para deducir información es como llamar a una puerta y distinguir si no hay nadie en casa (usuario no existe) de si hay alguien pero no te abre (usuario existe, contraseña incorrecta). La puerta te está diciendo más de lo que debería
