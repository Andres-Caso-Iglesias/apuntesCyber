**Repaso completo de NFS: montar, leer hashes y trabajar con claves SSH**

NFS (Network File System, puerto 2049) permite compartir carpetas en red en sistemas Linux, de forma análoga a las carpetas compartidas de SMB en Windows. En Metasploitable 2, la raíz completa del sistema está compartida, lo que convierte este servicio en el vector de mayor impacto de toda la máquina.

El flujo completo para explotar NFS es:

```
showmount -e IP_OBJETIVO
```

Esto lista las carpetas compartidas. Si aparece / con acceso *, todo el sistema de ficheros está accesible para cualquier IP. Se crea una carpeta local y se monta la carpeta compartida en ella:

```
mkdir ~/Desktop/carpeta_meta2
sudo mount -t nfs IP_OBJETIVO:/ ~/Desktop/carpeta_meta2
```

Dos errores frecuentes en este punto: olvidar el sudo (sin él el montaje falla por permisos) y omitir los dos puntos seguidos de la barra antes del directorio compartido. La sintaxis exacta es IP:/ ruta_local.

Una vez montado, el sistema de ficheros de la máquina objetivo es accesible localmente. Esto permite leer /etc/shadow, que contiene los hashes de contraseñas de todos los usuarios. Los hashes con * o ! al inicio corresponden a cuentas deshabilitadas.

**Identificar y romper hashes**

El prefijo del hash indica el algoritmo: $1$ es MD5, $5$ es SHA-256, $6$ es SHA-512. La herramienta hash-identifier confirma el tipo pasándole el hash como argumento.

Con John the Ripper, especificando el formato:

```
john --format=md5crypt --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
john --show hashes.txt
```

John guarda los hashes rotos en una base de datos interna. Para ver resultados de una sesión anterior sin relanzar el ataque:

```
john --show hashes.txt
```

Con Hashcat, localizando el modo correcto en su documentación (modo 500 para MD5crypt):

```
hashcat -m 500 hashes.txt /usr/share/wordlists/rockyou.txt
```

Una advertencia práctica: RockYou es un diccionario enorme. Lanzarlo completo puede congelar la máquina virtual, especialmente con poca RAM o GPU limitada. En ese caso, Ctrl+C para interrumpir y revisar los resultados parciales con john --show.

- **La idea clave:** romper hashes no es el objetivo final, es un medio. Las contraseñas obtenidas sirven para acceder a otros servicios de la misma máquina, ya que los usuarios del sistema pueden tener la misma contraseña en varios servicios

**Claves SSH a través de NFS: robar y plantar**

Con acceso al sistema de ficheros completo via NFS, se puede acceder al directorio oculto .ssh de cualquier usuario:

```
ls -la ~/Desktop/carpeta_meta2/home/msfadmin/.ssh/
```

Dentro hay tres ficheros: id_rsa (clave privada), id_[rsa.pub](http://rsa.pub/) (clave pública) e authorized_keys (lista de claves públicas autorizadas a conectarse).

**Vector 1 — Robar la clave privada existente**

Se copia la clave privada, se le dan los permisos correctos y se usa para conectarse:

```
cp ~/Desktop/carpeta_meta2/home/msfadmin/.ssh/id_rsa .
chmod 600 id_rsa
ssh -i id_rsa root@IP_OBJETIVO
```

En este caso concreto, la clave privada encontrada en la carpeta de msfadmin no funciona para conectarse como msfadmin (pide contraseña, probablemente la clave está protegida), pero la misma clave pública está también en authorized_keys del usuario root. Por eso al cambiar el usuario a root en el comando SSH la conexión funciona sin contraseña.

**Vector 2 — Plantar una clave propia (persistencia)**

Se genera un par de claves nuevo, sin contraseña para la clave privada:

```
ssh-keygen -t rsa
```

Se añade la clave pública generada al authorized_keys de root. Como la carpeta compartida NFS está montada en tiempo real, escribir en ella equivale a escribir directamente en el sistema remoto. Usar >> (doble flecha) añade sin sobreescribir:

```
cat id_rsa.pub >> ~/Desktop/carpeta_meta2/root/.ssh/authorized_keys
chmod 600 id_rsa
ssh -i id_rsa root@IP_OBJETIVO
```

La conexión funciona porque la clave pública está ahora autorizada. Esto establece persistencia: aunque se cambien contraseñas, la clave plantada sigue permitiendo acceso.

- **La metáfora útil:** authorized_keys es el listado de personas que tienen llave de tu casa. Si alguien añade su llave pública ahí, puede entrar siempre, independientemente de si cambias la cerradura (contraseña)

El usuario obtenido es postgres, la cuenta de servicio de la base de datos. Como en sesiones anteriores, cada servicio comprometido da acceso al usuario asociado a ese servicio, no directamente a root. Desde aquí, sudo -l no muestra privilegios adicionales.

Apache Tomcat es un servidor de aplicaciones Java que expone un panel de administración en el puerto 8180. La explotación sigue el mismo esquema de dos pasos: primero credenciales, luego exploit autenticado.

**Puerto 80 — Primera aproximación al hacking web**

La sesión cierra con una introducción práctica a las vulnerabilidades web, usando la aplicación DVWA (Damn Vulnerable Web Application) incluida en Metasploitable 2.

**robots.txt: el mapa de lo que no quieren que veas**

El fichero robots.txt indica a los motores de búsqueda qué URLs no indexar. Precisamente por eso es el primer lugar donde buscar: todo lo que el dueño de la web no quiere que aparezca en Google está listado ahí. En Metasploitable 2, el robots.txt de una de las aplicaciones lista directorios como /passwords/ y /config/:

- /passwords/ contiene un fichero con usuarios y contraseñas en texto claro
    
- /config/[config.inc](http://config.inc/).php contiene las credenciales de conexión a la base de datos MySQL: usuario root, contraseña vacía, host [localhost](http://localhost/)
    

Con estas credenciales se accede directamente a MySQL desde la terminal:

```
mysql -h IP_OBJETIVO -u root
```

Y se puede explorar la base de datos de la aplicación web. En DVWA, la tabla users contiene usuarios y contraseñas hasheadas (MD5 en este caso, identificable porque hash-identifier lo confirma).

**Fuzzing de directorios con Feroxbuster**

Además de FFUF y DirBuster (vistos en sesiones anteriores), Feroxbuster es una herramienta que realiza fuzzing recursivo: encuentra un directorio y automáticamente busca subdirectorios dentro de él, lo que aumenta considerablemente la cobertura:

```
feroxbuster --url http://IP_OBJETIVO/mutillidae/
```

Encuentra directorios y ficheros que las herramientas no recursivas pueden pasar por alto.

**Command Injection: primera vulnerabilidad web en acción**

En DVWA hay un módulo de Command Injection que simula una herramienta de ping. La aplicación espera una IP, lanza un ping y muestra el resultado. Si la validación de entrada no está correctamente implementada en el servidor, se pueden encadenar comandos adicionales:

```
127.0.0.1; cat /etc/passwd
```

El punto y coma termina el comando ping y encadena la lectura de /etc/passwd. El servidor ejecuta ambos y devuelve la salida de los dos. La aplicación procesa código del lado del servidor, lo que convierte cualquier fallo de validación en ejecución remota de comandos.

Esta distinción conceptual es importante: no es un RCE clásico (ejecución desde una máquina remota externa), sino una ejecución local en el servidor que el atacante puede controlar a través de la entrada de usuario. El principio es el mismo que con FTP combinado con la web: cuando el servidor interpreta lo que el usuario introduce, la superficie de ataque se amplía radicalmente.

- **La idea clave:** la fase de reconocimiento web no termina cuando abres la página principal. robots.txt, ficheros de configuración accidentalmente públicos, subdirectorios con diccionarios, paneles de administración por defecto: todo esto forma parte de la enumeración y muchas veces entrega las credenciales o la vulnerabilidad directamente
    

---

**Recapitulación integrada**

Al cerrar esta sesión hemos completado prácticamente todos los vectores de explotación de Metasploitable 2. NFS con la raíz compartida permite leer hashes, romperlos y manipular las claves SSH para establecer persistencia. PostgreSQL y Apache Tomcat siguen el mismo esquema de dos fases: credenciales por fuerza bruta o fuga de información, seguidas de exploit autenticado que da acceso a la cuenta de servicio correspondiente. Y en la parte web hemos confirmado que la enumeración (robots.txt, ficheros de configuración, fuzzing recursivo) es tan importante como la explotación: en este caso, el fichero de configuración entregó las credenciales de la base de datos sin necesidad de lanzar ningún ataque. La próxima sesión arranca el módulo de hacking web en profundidad: XSS, SQLi, LFI y el uso completo de Burp Suite.
