HTB no es solo un catálogo de máquinas. Tiene varias secciones con propósitos distintos:

- **HTB Labs:** el catálogo principal. Aquí viven las máquinas vulnerables con flags de usuario y de root/admin. Las máquinas **activas** rotan periódicamente y las gratuitas son accesibles para todos. Las máquinas **retiradas** requieren suscripción VIP pero permiten acceder a writeups oficiales. Es donde más tiempo se va a pasar durante el máster
    
- **Starting Point:** subsección de Labs con máquinas diseñadas para primeros pasos. Organizadas en Tier 0, Tier 1 y Tier 2, en orden creciente de dificultad. Las no marcadas como VIP son completamente gratuitas
    
- **HTB Academy:** plataforma de aprendizaje guiado con módulos organizados por tiers de dificultad. Buena referencia para profundizar en un área concreta. Tiene sus propias certificaciones (CPTS, CBBH) a unos 400€, asequibles comparado con el sector, pero con poco reconocimiento corporativo actual. Se recomienda usar la Academia como complemento, no como sustituto de hacer máquinas
    
- **Challenges:** retos aislados por categoría (web, reversing, crypto, OSINT, forense). Lo que hicimos con el laboratorio de YellowRat era este tipo de reto
    
- **Tracks:** rutas temáticas que agrupan máquinas y challenges sobre un tema concreto (directorio activo, blockchain, WiFi). Útiles para preparar un área específica
    
- **ProLabs:** entornos corporativos completos con múltiples máquinas de directorio activo. Nivel avanzado, pago aparte de la suscripción, pero incluyen un certificado propio al completarlos
    
- **Fortresses:** laboratorios creados por empresas externas (AWS, Palo Alto, etc.) alojados en HTB. Demuestran cómo explotar sus propias plataformas de forma controlada
    

El perfil de HTB es público y consultable. Los reclutadores técnicos lo revisan. Cuantas más máquinas completadas, más señal real de práctica acumulada.

**Conectarse a HTB: VPN y metodología básica**

HTB funciona con redes privadas separadas. Para acceder a las máquinas hay que conectarse a su VPN específica. Las redes de **Starting Point** y las de **Machines** son independientes: el fichero de VPN de una no sirve para la otra.

Para descargar el fichero:

```
# En HTB: Connect (arriba a la derecha) → Starting Point → OpenVPN → Download
```

Para conectarse desde Kali:

```
sudo openvpn nombre_del_fichero.ovpn
```

La terminal donde se lanza queda ocupada mostrando el log de la VPN. Se deja abierta durante toda la sesión. En otra terminal, para verificar que la conexión es correcta:

```
ifconfig
```

Debe aparecer un adaptador tun0 con una IP asignada. Esa es la IP que identifica a Kali dentro de la red de HTB. Todos los comandos de ataque usan la IP de la máquina objetivo, no esta.

Antes de atacar cualquier máquina, se crea la estructura de carpetas de trabajo:

```
mkdir meow && cd meow && mkdir recon
```

**Máquina 1 — Meow (Telnet)**

El primer escaneo con Nmap revela únicamente el puerto 23 abierto con servicio Telnet. Telnet es un protocolo antiguo de administración remota que transmite todo en texto claro, incluyendo credenciales. Está en desuso precisamente por eso: SSH lo reemplazó con cifrado.

La máquina está mal configurada: el usuario root no tiene contraseña asignada. El proceso de ataque:

```
nmap -sV -Pn -vvv -oA recon/meow IP_OBJETIVO
telnet IP_OBJETIVO
# Login: root
# Password: (enter vacío)
id
ls
cat flag.txt
```

Lección de esta máquina: siempre probar credenciales por defecto antes de cualquier otra técnica. root sin contraseña, admin/admin, administrator/administrator. Son las primeras pruebas de cualquier servicio de administración remota.

---

**Máquina 2 — Fawn (FTP)**

Nmap detecta el puerto 21 con VSFTPD 3.0.3. El escaneo con -sC confirma que las sesiones anónimas están habilitadas.

```
nmap -sV -sC -Pn -vvv -oA recon/fawn IP_OBJETIVO
ftp IP_OBJETIVO
# Name: anonymous
# Password: (enter vacío)
ls
get flag.txt
bye
cat flag.txt
```

Recordatorio de conceptos clave de FTP vistos con Metasploitable: el modo activo puede fallar detrás de firewalls, el modo pasivo (PASV) suele funcionar mejor. get descarga un fichero, mget * descarga todo el contenido de la carpeta actual. FTPS y SFTP son las versiones seguras que cifran el canal.

- **La idea clave:** FTP anónimo en producción es una mala configuración grave. Cualquier persona con visibilidad de red puede conectarse, listar y descargar ficheros. Si encima hay carpetas con escritura, puede subir contenido malicioso que otros servicios ejecuten
    

---

**Máquina 3 — Dancing (SMB)**

Nmap detecta los puertos 135, 139, 445 y 5985. El puerto 445 corresponde a SMB, el protocolo de Microsoft para compartir ficheros, carpetas e impresoras en red. Samba es su implementación para Linux/Unix. SMB es omnipresente en entornos corporativos Windows, incluyendo directorio activo.

El flujo de ataque es: enumerar shares → identificar permisos → conectarse al share accesible → extraer la flag.

```
# Listar shares disponibles con sesión nula
smbclient -L //IP_OBJETIVO -N

# Ver permisos de cada share (más completo)
netexec smb IP_OBJETIVO -u '' -p '' --shares

# Conectarse al share con permisos de lectura
smbclient //IP_OBJETIVO/WorkShares -N
ls
cd Amy.J
ls
get worknotes.txt
cd ../James.P
ls
get flag.txt
bye
```

El guión -N indica sesión sin contraseña (null session). smbclient -L lista las shares pero no muestra permisos. **NetExec** (antes CrackMapExec) muestra qué permisos concretos tiene cada share, lo que evita probar una a una. Es la herramienta de referencia para SMB en entornos Windows.

Las cuatro barras (//IP/Share) son la convención UNC de Windows para rutas de red. get funciona igual que en FTP para descargar ficheros.

**Filosofía de uso de HTB: el aviso sobre la IA y los writeups**

Yuba cierra la sesión con una advertencia directa. Usar IA o writeups para resolver máquinas sin haberlas intentado antes es contraproducente a largo plazo. Las pruebas técnicas de empresas como KPMG son CTFs en vivo con proctoring. Las auditorías reales a clientes no permiten enviar datos a modelos externos por GDPR. Cuando llegue ese momento, o se sabe o no se sabe.

El proceso recomendado es: intentar la máquina sin ayuda, pelearse con ella, buscar en HackTricks y en documentación oficial. Si después de un esfuerzo real no se avanza, se puede usar la IA para pistas concretas, no para que lo resuelva. Y una vez resuelta, repetirla automatizando pasos con scripts, eso sí tiene sentido con IA.

- **La idea clave:** el perfil de HTB tiene valor precisamente porque demuestra horas reales de práctica. Cincuenta máquinas hechas con writeups no enseñan nada y no engañan a quien hace la entrevista técnica
