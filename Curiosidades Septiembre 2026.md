## 🎯 Metodología de pentesting web

**Clase:** 15.09.2026

- **Paso 1:** Mapear la aplicación (clicar TODOS los botones con Burp)
- **Paso 2:** Identificar parámetros (ordenar por "params" en HTTP History)
- **Paso 3:** Fuzzear con Intruder (lanzar payloads y buscar respuestas diferentes)
- **Paso 4:** Analizar status code, longitud, errores y timeouts
- **Los parámetros** son los puntos de entrada donde el usuario puede meter texto libre
- Un parámetro en login ≠ un parámetro en subida de archivos → vulnerabilidades diferentes
- En auditorías corporativas es **inviable** testear todos los parámetros (pueden ser 200+)

> 💡 **Consejo de Yuba:** "Si veis algo diferente en Intruder (un 500 cuando todos dan 302), AHÍ HAY ORO."

## 📊 Datos técnicos sueltos

| Dato | Contexto |
|---|---|
| **TTL 63 = Linux**, TTL 128 = Windows | Para identificar SO desde un ping |
| **MD5 es frágil** | Cualquier hash se crackea con tablas (RockYou + John) |
| **Oracle siempre necesita FROM** | Usar `DUAL` como tabla por defecto |
| **`--` comenta el resto** de la query en MySQL | En Oracle puede necesitar espacio: `-- ` |
| **`OR 1=1`** siempre es verdadero | Para bypass de condiciones |
| **Las comillas** separan datos de código SQL | Al romperlas, todo lo que metemos es código |
| **Foxy Proxy** se ha puesto de pago | Alternativa: configuración manual del proxy |
