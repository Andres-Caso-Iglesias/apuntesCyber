## ① Arquitectura de una página web — Front, Back y Base de Datos

Una página web no es una cosa estática. Tiene tres capas que se comunican entre sí:

| Capa | Qué es | Accesible por |
|---|---|---|
| **Front-end** | Lo que ve el usuario (HTML, CSS, botones) | El usuario |
| **Back-end** | Servidor que procesa peticiones (PHP, .NET) | La aplicación |
| **Base de datos** | Almacén de datos (MySQL, PostgreSQL) | Solo el back-end |

### El ciclo de una petición web

1. El usuario hace una petición (request) desde el front
2. El front envía la request al servidor (back-end)
3. El back-end procesa la petición y consulta la base de datos
4. La base de datos responde con los datos
5. El back-end rellena una **template** (plantilla PHP) con esos datos
6. El usuario recibe la página completa (response)

> [!important] Las páginas web NO están precargadas
> Cuando entras en Zara y ves el catálogo, lo que ocurre es: el front hace una petición al back → el back consulta la BD → la BD devuelve los productos → el back rellena la template → te muestra la página. Cada visita genera una query diferente.

### Las templates (plantillas)

Una template es una página con **espacios en blanco** que se rellenan con datos de la base de datos:

```
[ESPACIO FOTO] [ESPACIO TEXTO]
[ESPACIO FOTO] [ESPACIO TEXTO]
```

Cada espacio tiene su propia sentencia SQL que trae los datos correspondientes.

## ② SQL — El lenguaje de las bases de datos

### Qué es una base de datos

Una base de datos es un **Excel muy grande** con columnas (atributos) y filas (registros). Ejemplo:

| id | nombre | categoría | precio |
|---|---|---|---|
| 1 | Camiseta | Ropa | 25€ |
| 2 | Pantalón | Ropa | 40€ |
| 3 | Zapatillas | Calzado | 80€ |

### Las tablas

Una BD tiene **múltiples tablas**, como secciones de una biblioteca:
- Tabla `ropa`
- Tabla `calzado`
- Tabla `accesorios`

### Una query (consulta)

```sql
SELECT foto, descripcion FROM productos WHERE categoría = 'pantalones';
```

| Parte | Qué hace |
|---|---|
| `SELECT` | Selecciona los **atributos** (columnas) que quiero ver |
| `FROM` | De qué **tabla** quiero los datos |
| `WHERE` | **Condición** que debe cumplir (a qué fila) |

### Tipos de consultas más comunes

| Consulta | Qué hace |
|---|---|
| `SELECT * FROM usuarios` | Selecciona TODO de la tabla usuarios |
| `SELECT nombre, email FROM usuarios WHERE id=1` | Selecciona nombre y email del usuario con id=1 |
| `SELECT * FROM productos WHERE categoría='ropa' AND precio<50` | Productos de ropa menos de 50€ |

## ③ La comunicación Front ↔ Back ↔ BD

### Dónde están los puntos de ataque

```
USUARIO → [FRONT] → [BACK] → [BASE DE DATOS]
              ↑          ↑           ↑
         Peticiones   Queries    Datos
         HTTP         SQL        Tablas
```

| Zona | Tipo de ataque |
|---|---|
| Front → Back | XSS, CSRF, inyección de comandos |
| Back → BD | **SQL Injection** |
| Back (servidor) | RCE, LFI, escalada de privilegios |

> [!important] El usuario NUNCA accede directamente a la BD
> El usuario habla con el front. El front habla con el back. El back habla con la BD. Si el back no valida bien lo que le llega, el atacante puede inyectar código SQL que se ejecuta en la BD.

## ④ Niveles de seguridad — Firewalls y WAF

### WAF (Web Application Firewall)

El primer cortafuegos que se encuentra el atacante. Se ubica **entre el usuario y el servidor**.

| Tipo | Funcionamiento |
|---|---|
| **Blacklist** | Permite todo y bloquea lo "malo" (más cómodo pero bypassable) |
| **Whitelist** | Bloquea todo y solo permite lo "bueno" (más seguro pero trabaja) |

> [!warning] Bypass de WAF con Burp Suite
> Burp Suite intercepta la petición **antes** de llegar al WAF. Si modificas la petición en Burp y la reenvías, puedes saltarte la blacklist del WAF.

### Firewall de servidor (EDR/SIEM)

Un segundo firewall **dentro del servidor** que:
1. Analiza el contenido (static analysis)
2. Detecta si es potencialmente peligroso
3. Envía al SIEM (correlacionador de eventos)
4. El SIEM bloquea la petición

### Firewall entre servidor y BD

Un tercer filtro **entre el servidor y la base de datos** para validar las queries.

### Cloudflare como WAF

Cloudflare es la infraestructura WAF más utilizada. Funciona como:
- **Proxy inverso**: oculta la IP real del servidor
- **Anti-DDoS**: filtra tráfico malicioso
- **WAF**: analiza peticiones con listas negras
- **CDN**: cache para que la web vaya más rápido

> [!info] Cloudflare protege el 80% del tráfico mundial
> Esto tiene implicaciones: si Cloudflare cae, caen miles de webs. España tuvo problemas con la Liga de Fútbol y Cloudflare por temas de IPTV y piratería.

## ⑤ DNS — Cómo funciona la resolución de nombres

Cuando escribes `zara.com`, no estás llamando a un nombre, sino a una **IP**:

```
zara.com → DNS Server → 96.168.208.X → Responde la web
```

Los **DNS Service** son servidores que traducen nombres de dominio a IPs. Cloudflare ofrece gestión DNS como parte de su servicio.

### Dominios

| Dominio | País/Entidad |
|---|---|
| `.com` | Comercial (global) |
| `.es` | España (red.es) |
| `.tv` | Tuvalu (viven de la venta de dominios) |
| `.ai` | Anguila (muy caro) |
| `.cat` | Cataluña (solo en catalán) |

## ⑥ Lámparas de lava y la seguridad de Internet

> [!info] Dato curioso
> Cloudflare genera sus certificados SSL/TLS usando **100 lámparas de lava** con cámaras de seguridad. Las burbujas de lava tienen posiciones completamente aleatorias, y esa aleatoriedad se usa para generar claves de cifrado.

```
Posición de burbujas (foto) → Hexadecimal → Clave de 100 dígitos
         ↓
XOR con segunda foto → Clave de cifrado SSL/TLS del día
```

Esto significa que la seguridad de Internet depende de la aleatoriedad de unas lámparas de lava.

## ⑦ Consultas SQL más utilizadas

### Funciones de cada parte de la query

| Parte | Controla | Vulnerabilidades |
|---|---|---|
| `SELECT` | Los campos que devuelve | UNION attacks |
| `FROM` | De qué tabla | Lectura de otras tablas, information_schema |
| `WHERE` | Las condiciones | Bypass de condiciones, OR 1=1 |

### UNION JOIN — Unir tablas

| Tipo | Qué hace |
|---|---|
| `LEFT JOIN` | Tabla izquierda como primaria, datos de la derecha |
| `RIGHT JOIN` | Tabla derecha como primaria, datos de la izquierda |
| `INNER JOIN` | Unifica por igual ambas tablas |

### Otras funciones útiles

| Función | Qué hace |
|---|---|
| `ORDER BY` | Ordena resultados (asc/desc) |
| `COUNT` | Cuenta registros |
| `UNION` | Une dos tablas en una sola consulta |

## ⑧ SQL Map — Automatización de extracción

**SQL Map** es una herramienta que automatiza la extracción de bases de datos:

```bash
sqlmap -u "http://target/page?id=1" --dbs
```

Con SQL Map puedes:
- Detectar si hay SQLi
- Identificar el tipo de BD (MySQL, PostgreSQL, etc.)
- Extraer tablas, columnas y datos
- Ejecutar comandos en el servidor

> [!tip] SQL Map vs Manual
> SQL Map es rápido y cómodo, pero para entender qué está pasando por detrás es necesario hacerlo manualmente. La semana veremos SQL Map en profundidad.

## ⑨ Notas de clase

- **Las páginas web son templates PHP** que se rellenan con datos de la BD
- **El front nunca habla con la BD** directamente; lo hace el back-end
- **Los WAF son bypassables** con Burp Suite si usan blacklist
- **Cloudflare protege el 80% de Internet** y genera certificados con lámparas de lava
- **Una query SQL tiene tres partes**: SELECT (qué), FROM (de dónde), WHERE (condición)
- **El backend es un usuario de servicio** (ej: www-data en Apache)
- **NUNCA tener la BD en el mismo servidor** que la aplicación web
- **SQL Map automatiza** la extracción, pero hay que entender el manual primero
