## ① El negocio del vibe coding €” monetización y upselling

### El caso real: cliente paga 4.000 € por un rediseño hecho en 3 prompts

Carlos abrió la clase mostrando la página que creó **durante la clase anterior** con tres prompts a Claude, para un cliente que pagó 4.000 € por rediseñar su web. La demo no era un alarde técnico, era una **tesis de negocio**:

| Servicio | Coste real (tokens) | Precio al cliente | Recurrencia |
|----------|---------------------|-------------------|-------------|
| Web rediseñada con IA | 0,10 € | 4.000 € | €” |
| Cobros online (Stripe) | 1 prompt | 1.500 € | 300 €/mes |
| Automatización facturas (OCR) | librería Python | 1.500 € | 200 €/mes |
| Contabilidad automatizada | módulo propio | 2.000 € | 200 €/mes |
| Generación leads (email agent) | 2 días setup | €” | 1.000 €/mes |
| **Total recurrencia** | €” | €” | **~800 €/mes** |

> [!important] La regla del upselling
> 1. Detectas el **dolor** del cliente (web lenta, fea, no vende).
> 2. Lo resuelves **rápido** y **barato** con IA → ganas **confianza**.
> 3. Con la confianza, le vendes lo **siguiente que necesita** (automatizaciones que él ni sabía que existían).
> 4. La IA es el **habilitador**; el **criterio de negocio** es el diferencial.

> [!note] La mentalidad del "cliente triste → cliente feliz"
> - Cliente triste: desconfía, tiene una web mierda, pagó a otra empresa que no entregó.
> - Resuelves su dolor en 24h → cliente feliz → confía en ti.
> - **Ahora** es cuando haces upselling: "ya que tienes e-commerce, te automatizo cobros/facturas/contabilidad/leads".
> - El cliente **no contrata tecnología**, contrata **que le quites problemas**.

## ② Cómo pensar un producto con IA €” el caso de John (finanzas personales)

Se usó la idea de John (app de finanzas personales) como **ejercicio en directo** de estructuración de MVP. El proceso **no empieza con código**, empieza con conversación:

```
PROMPT A CLAUDE:
"Tengo una idea para una app web de gestión de finanzas personales.
Necesito que me ayudes a refinar, mejorar y, lo más importante,
darle un valor diferencial sobre los competidores (Fintonic, Spendee, etc.).

1. Sácame una tabla de la competencia con features.
2. Mi idea tiene estos puntos: regla 50-30-20 personalizable (no dogma),
 agente que analice situación real y proponga plan de acción adaptado.
3. Dame un prompt hiperdetallado para pasárselo a Claude Code y genere el MVP v1."
```

### Lo que Claude devuelve (resumen)

| Competidor | Qué falla | Nuestro diferencial |
|------------|-----------|---------------------|
| Fintonic | IA real no funciona, 50-30-20 rígido, gestión préstamos vende sin optimizar, deudas terceros no mira, alertas comisiones no | **Asesor inteligente** que analiza situación real y propone plan adaptado (no dogma) |
| Spendee | Similar | **Personalización real**: si no puedes 50-30-20, haces 60-20-20 con principio de adaptación |
| Otras | Venden productos, no asesoran | **Regla 50-30-20 + principio de personalización + agente proactivo** |

> [!important] Prompts grandes = mejor resultado
> "Los prompts grandes son prompts autoexplicativos. Un prompt autoexplicativo deja menos libertad a la IA para desviarse (se fuman menos porros). Cuando la IA se fuma pocos porros, está mucho más centrada en lo que queremos."

## ③ Claude Code €” configuración inicial y optimización de tokens

### Pasos prácticos hechos en directo

```bash
# 1. Instalar Claude Code
curl -fsSL https://claude.ai/install.sh | bash

# 2. Saltar permisos (modo YOLO)
claude --dangerously-skip-permissions

# 3. Instalar RDK (Research Development Kit)
# RDK = skills para que Claude use comandos del sistema (cat, grep, find)
# en lugar de sus comandos internos → ~80% menos tokens
claude install rdk

# 4. Configurar selección inteligente de modelos en claude.md
# Haiku → búsquedas y ops simples
# Sonnet → desarrollo estándar
# Opus → solo razonamiento complejo
```

### ¿Por qué RDK ahorra ~80% tokens?

| Sin RDK | Con RDK |
|---------|---------|
| Claude lee y procesa **cada fichero** él mismo | Usa `cat`, `grep`, `find` del sistema |
| Procesa contenido completo en contexto | Lee solo lo necesario, el SO hace el trabajo pesado |
| Gasta tokens en I/O | Gasta tokens solo en razonamiento |

> [!warning] Configuración clave en `claude.md`
> ```
> - Selecciona SIEMPRE el modelo más adecuado: Haiku (simple), Sonnet (dev), Opus (complejo)
> - Usa RDK por defecto para operaciones de fichero
> - Añade reglas al claude.md para que sean persistentes
> ```

## ④ Subagentes especializados €” diseño, bronzer/prompter, selector de modelo

Carlos construyó **tres subagentes** en directo que se añaden a `claude.md` como skills permanentes:

### 1. Agente de Diseño (Design Researcher)
```
"Antes de crear cualquier interfaz, haz deep research sobre competidores del sector.
Extrae patrones UX, colores, tipografía. Genera guía de estilos adaptada a ese nicho.
Resultado: diseño que NO parece generado por IA porque está basado en investigación real de mercado."
```

### 2. Agente Bronzer / Prompter (Intermediario)
```
"Actúas de intermediario entre el usuario y cualquier otro agente.
Recibes el prompt del usuario, lo mejoras, lo estructuras y se lo pasas al agente final.
Permite que prompts informales y cortos generen resultados equivalentes a prompts de 20 páginas."
```

### 3. Selector de Modelo (Model Router)
```
"Analiza la tarea y decide qué modelo usar:
- Haiku: búsquedas, ops simples, clasificación
- Sonnet: desarrollo estándar, refactor, features
- Opus: SOLO razonamiento complejo, arquitectura, debugging profundo
Evita que tareas triviales consuman tokens de modelos caros."
```

> [!tip] El patrón maestro
> `Usuario → Bronzer (optimiza prompt) → Agente Especializado (Diseño/Dev/Research) → Modelo Adecuado (Haiku/Sonnet/Opus)`
> Cada capa filtra y mejora. El usuario escribe en lenguaje natural; el sistema se encarga de la ingeniería de prompts.

## ⑤ Redes neuronales y ontologías €” el nivel teórico profundo

La conversación derivó hacia una **distinción técnica fundamental** entre dos formas de organizar conocimiento para una IA.

### Grafo de índices (Obsidian, Notion) vs Red Neuronal con Ontologías

| Aspecto | Grafo de índices (Obsidian) | Red Neuronal + Ontologías |
|---------|----------------------------|---------------------------|
| **Conexión** | Hipervínculo vacío: A → B | Relación semántica: "gato **juega con** pelota" |
| **Contexto** | Ninguno (solo referencia) | Lenguaje natural: por qué y cómo se relacionan |
| **Inferencia** | No | Sí: herencia, analogía, razonamiento |
| **Nodo nuevo** | Aislado hasta que se linkea manual | Se conecta automático por ontología (pelota fútbol →” pelota baloncesto = ambas son pelotas) |
| **Uso ideal** | Bases de datos consulta simple | Aprendizaje real, diagnóstico, simulación |

### El ejemplo del gemelo digital felino (clínica veterinaria de Carlos)

Carlos está construyendo una **red neuronal con ontologías** para simular cómo reacciona un medicamento a nivel molecular en cada órgano de un gato:

```
Átomo → Molécula → Célula → Tejido → Ã“rgano → Sistema → Gato
 →“ →“ →“ →“ →“ →“
 conectados por ontologías: "el átomo forma parte de la molécula",
 "la célula contiene moléculas", "el tejido está hecho de células",
 "el órgano está compuesto de tejidos", etc.
```

**Pregunta:** "Si doy vía oral medicamento X, ¿cómo reacciona en todos los órganos?"
**Respuesta:** La red recorre las ontologías: conoce composición molecular del fármaco, qué receptores toca, qué vías metabólicas activa, cómo afecta a cada célula/tejido/órgano, y simula evolución temporal.

> [!note] La metáfora útil
> - **Índice de páginas (Obsidian):** Biblioteca con tarjetas de catálogo. Sabes dónde está cada libro.
> - **Red neuronal + ontologías:** Cerebro que no solo sabe dónde está cada libro, sino que **entiende de qué hablan y cómo se relacionan entre sí**.

### Pesos numéricos vs Ontologías (contexto semántico)

| Modelo tradicional (pesos) | Modelo con ontologías |
|----------------------------|----------------------|
| Elige opción **estadísticamente más probable** | Elige opción **semánticamente correcta** |
| "Gato + pelota → no juega" (peso mayor en dataset: gatos no juegan) | "Gato + pelota → **juega con** pelota" (ontología: gato juega con pelota) |
| Falla en contexto atípico | Entiende la relación por significado |

> [!important] Cuándo usar cada arquitectura
> - **Índice plano (Obsidian/Notion):** Info estática, consulta simple, búsqueda por palabra clave.
> - **Red neuronal + ontologías:** Aprendizaje real, diagnóstico médico, comportamiento usuarios, simulación molecular, gemelos digitales, correlación multi-nivel.

## ⑥ Arquitectura de conocimiento €” Obsidian vs Neo4j

| Herramienta | Dimensión | Qué es | Cuándo usarla |
|-------------|-----------|--------|---------------|
| **Obsidian** | 2D (plano) | Grafo de índices / hipervínculos | Base de datos consulta simple, notas, documentación proyecto |
| **Neo4j** | 3D (neuronal) | Grafo con ontologías / relaciones semánticas | Aprendizaje, inferencia, diagnóstico, simulación compleja |

**Flujo híbrido de Carlos:**
1. Busca en **Obsidian** (grafo de notas) → encuentra nodos relevantes
2. Lanza consulta a **Neo4j** (red neuronal) → obtiene respuesta optimizada con contexto
3. Resultado: no recorre 150M neuronas, usa índice para acotar y red neuronal para profundizar

### Poda (pruning) y ontología

- **Poda:** Eliminar nodos redundantes que aportan misma info → aligera red, evita iteraciones inútiles.
- **Ontología:** Relación en lenguaje natural entre nodos ("tiende a", "puede", "no quiere") en lugar de peso numérico. Permite generalizar: si "balón fútbol es redondo" y "balón fútbol = balón baloncesto", entonces "balón baloncesto es redondo" **sin haberlo visto**.

## ⑧ Gestión de proyectos, tokens y contexto €” claude.md, auditorías, Obsidian

### El problema del contexto finito

> "La memoria de Cloud es finita. Es el **contexto de un LLM**. Cuando se acaba, pierdes la info. Por eso es mejor tenerlo todo documentado en `.md`."

### Flujo de cambio de cuenta/herramienta sin perder contexto

```bash
# 1. En proyecto actual
claude "hazme una auditoría completa de mi proyecto"
# → genera AUDITORIA.md con: arquitectura, decisiones, estado, próximos pasos

# 2. Cambias de herramienta (Cursor, otra cuenta Claude, etc.)
# 3. En nueva herramienta:
claude "revisa el AUDITORIA.md de mi proyecto. ¿En qué punto estamos? ¿Qué sigue?"
```

### Estructura recomendada de documentación viva

```
/proyecto/
│”œ── CLAUDE.md # System prompt, skills, reglas, subagentes
│”œ── AUDITORIA.md # Estado actual, decisiones, debt técnico, next steps
│”œ── ARQUITECTURA.md # Diagramas, decisiones de infra, seguridad
│”œ── PRODUCTO.md # Requisitos, roadmap, diferenciadores
│”œ── AGENTES.md # Subagentes definidos, skills, prompts base
┘── /docs/ # Auditorías específicas (seguridad, tests, perf)
```

> [!tip] Obsidian como "cerebro externo indexado"
> - Páginas con hipervínculos = grafo de índices 2D
> - Plugin **Graph View** = navegación visual
> - Sirve para **buscar y acotar** antes de lanzar a red neuronal (Neo4j)
> - **No es red neuronal**: no tiene ontologías, solo referencias vacías

## ⑨ Neurodivergencia, gemelos digitales y sesgos €” la conversación profunda

### El caso de Mariana (app neurodivergencias)

| Problema | Solución propuesta por Carlos |
|----------|-------------------------------|
| Escaneo facial menores = ilegal (datos biométricos sensibles) | **No guardar datos biométricos**. Solo extraer 57 cadenas biométricas → edad estimada → descartar imagen. Validación, no verificación. |
| Sesgo estudios autismo (hombre, blanco, varón) | **Limpiar el modelo**: crear red por característica (género, altura, raza, cultura), podar sesgos, dejar red "clean" solo para análisis conductual. |
| Triple excepcionalidad (autista + altas capacidades + TDAH) | Red neuronal por niño → cerebro común (patrones compartidos) + cerebro individual (patologías propias) → red superior que correlaciona y detecta nuevos patrones cross-paciente. |

### Gemelo digital felino (clínica veterinaria)

- **Niveles:** Átomo → Molécula → Célula → Tejido → Ã“rgano → Sistema → Gato
- **Ontologías:** Relaciones semánticas entre niveles (no pesos numéricos)
- **Simulación:** "Si doy fármaco X oral, ¿cómo evoluciona el gato en 6 meses?"
- **Entrenamiento:** Deep research en artículos científicos veterinarios verificados → absorbe → correlaciona síntomas/enfermedades/tratamientos → aprende por qué funciona cada medicamento.

### Red neuronal por niño + red superior (neurodivergencias)

```
Niño 1 (red propia) ──│”
Niño 2 (red propia) ──│”¤ → Red superior (patrones comunes, correlaciones cross-paciente)
Niño 3 (red propia) ──│”˜ → Detecta doble/triple excepcionalidad
 → Aísla síntomas reales
 → Genera nuevo conocimiento médico
```

> [!important] Sesgos en IA médica
> - Estudios autismo basados en **varón, blanco, occidental** → diagnosticar niña = difícil (enmascara).
> - **Solución:** No "desentrenar", sino **limpiar**: crear red por característica (género, altura, raza, cultura), podar de la red principal, dejar solo red analítica limpia.
> - Cada IA responde distinto a cada usuario porque **tiene un modelo neuronal del usuario** (sus características, expectativas, contexto).

## ⑪ Conceptos clave para recordar

| Concepto | Definición |
|----------|------------|
| **Vibe Coding** | Desarrollar dejando que la IA genere código mientras tú diriges arquitectura, criterio de negocio y validación |
