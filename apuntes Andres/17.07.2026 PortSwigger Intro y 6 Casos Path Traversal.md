## ③ Path Traversal — repaso conceptual

### ¿Qué es?

Cuando un parámetro de la URL acepta un nombre de fichero y el servidor hace una llamada a ese archivo, si **no sanitiza** las secuencias `../`, el atacante puede navegar fuera del directorio previsto.

```
Parámetro: filename=9.jpg
Servidor busca: /var/www/html/images/9.jpg

Parámetro: filename=../../../../etc/passwd
Servidor busca: /var/www/html/images/../../../../etc/passwd → /etc/passwd
```

### ¿Cómo detectarlo?

1. Observar en Burp parámetros tipo `filename=`, `file=`, `path=`
2. Buscar peticiones que **no aparecen en la URL visible** (imágenes, recursos en segundo plano)
3. Probar `../../../etc/passwd` como validación

> [!warning] Error clásico
> Muchos se centran solo en lo que ven en la URL. Las imágenes y recursos se cargan con peticiones internas que solo se ven interceptando con Burp.

### Diferencia Path Traversal vs LFI

```
Path Traversal → navegar entre directorios (el MECANISMO)
 ↓
LFI → leer ficheros locales no autorizados (la CONSECUENCIA)
```

> [!important] La metáfora de Carlos
> "El desarrollador ha dejado una puerta abierta que da a la calle, pensando que nadie saldría porque la puerta es pequeña. Path traversal es agacharse para pasar."

## ④ Los 6 casos de Path Traversal

### Caso 1 — Sin validación (el más simple)

**La aplicación:** carga imágenes con `filename=9.jpg`. Sin ningún filtro.

**Explotación:**
```
/image?filename=../../../etc/passwd
```

**Resultado:** devuelve `/etc/passwd` sin restricción alguna.

> [!important] Existe en producción
> Este caso se ve más frecuentemente de lo que debería. Desarrolladores que simplemente concatenan la entrada del usuario a una ruta sin sanitizar.

---

### Caso 2 — Bloqueo de `../`, bypass con ruta absoluta

**El servidor:** detecta `../` y lo rechaza.

**El truco:** usar ruta absoluta en lugar de relativa.

```
# NO funciona:
/image?filename=../../../etc/passwd

# SÍ funciona:
/image?filename=/etc/passwd
```

**¿Por qué funciona?**
- El desarrollador protegió contra `../` (ruta relativa)
- Pero olvidó que una **ruta absoluta** también puede apuntar a cualquier fichero
- El servidor interpreta `/etc/passwd` como ruta absoluta y se olvida del directorio previsto

> [!important] La lógica
> Cuando el servidor recibe `/etc/passwd`, lo detecta como ruta absoluta y omite toda la lógica de concatenación con `/var/www/html/images/`.

---

### Caso 3 — Eliminación no recursiva de `../`

**El servidor:** elimina las secuencias `../` del parámetro antes de procesarlo.

**El truco:** anidar `../` de modo que al eliminar la interior quede la exterior.

```
Entrada: ....//....//....//etc/passwd
Filtro: elimina ../
Resultado: ../../../etc/passwd
```

**Explotación:**
```
/image?filename=....//....//....//etc/passwd
```

**¿Por qué funciona?**
- El filtro busca `../` y lo elimina
- Pero `....//` contiene `../` en su interior
- Al eliminarlo, queda `../` → que es exactamente lo que queríamos

> [!warning] Filtros insuficientes
> Los filtros que eliminan cadenas **sin validar el resultado** son inseguros. Siempre hay que sanitizar recursivamente o usar whitelist de caracteres.

---

### Caso 4 — Bypass con URL encoding

**El servidor:** bloquea `../` como texto plano.

**El truco:** codificar los caracteres en URL encoding.

```
# Texto plano (bloqueado):
../

# URL encoding:
%2e%2e%2f
```

**Explotación simple:**
```
/image?filename=%2e%2e%2f%2e%2e%2f%2e%2e%2fetc%2fpasswd
```

**Explotación doble (si decodifica una vez):**
```
/image?filename=%252e%252e%252f%252e%252e%252f%252e%252e%252fetc%252fpasswd
```

**¿Por qué funciona el doble encoding?**
- `%25` = carácter `%` en URL encoding
- `%252e` → se decodifica a `%2e` → se decodifica a `..`
- El filtro solo ve la primera codificación y no reconoce el patrón

```
Flujo de decodificación:
%252e%252e%252f
 ↓ (decodifica 1 vez)
%2e%2e%2f
 ↓ (decodifica 2 veces)
../
```

> [!important] Cuántas veces decodifica
> No lo sabemos nunca. Hay que probar 1, 2, 3 veces como máximo. Si no funciona, pasar al siguiente caso.

---

### Caso 5 — Validación de ruta de inicio (requiere prefijo)

**El servidor:** valida que el parámetro empiece por una ruta conocida (`/var/www/html/images/`).

**El truco:** incluir el prefijo requerido y luego navegar hacia atrás.

```
# NO funciona (no empieza por la ruta esperada):
/image?filename=../../../etc/passwd

# SÍ funciona (empieza por la ruta correcta):
/image?filename=/var/www/html/images/../../../etc/passwd
```

**¿Por qué funciona?**
- El servidor ve que empieza por `/var/www/html/images/` → OK
- No verifica que el path resultante **después de resolver los `..`** siga dentro del directorio permitido

> [!important] Conocer la ruta inicial
> Muchas veces hay que descubrir la ruta por otras vías (errores, otros parámetros, etc.). En este caso nos la ponen fácil.

---

### Caso 6 — Validación de extensión con null byte

**El servidor:** valida que el parámetro termine con extensión de imagen (`.jpg`, `.png`).

**El truco:** usar null byte (`%00`) como terminador de cadena.

```
# NO funciona (no termina en extensión):
/image?filename=../../../etc/passwd

# SÍ funciona (termina en .png):
/image?filename=../../../etc/passwd%00.png
```

**¿Por qué funciona?**
- El servidor ve que termina en `.png` → OK
- Pero el null byte (`%00`) termina la cadena en el sistema operativo
- Lo que realmente se lee es `../../../etc/passwd`

```
Flujo:
Backend valida: ../../../etc/passwd%00.png → termina en .png ✓
Sistema opera: ../../../etc/passwd%00 → termina en %00 (null)
Resultado: lee ../../../etc/passwd
```

> [!warning] Contexto limitado
> Esto funciona principalmente en aplicaciones antiguas con funciones de C o ciertos contextos PHP. No es universal.

## ⑤ De Path Traversal a LFI — qué buscar después

### La progresión

```
1. Detectar path traversal → validar con /etc/passwd
 ↓
2. Pasar a LFI → buscar ficheros útiles
 ↓
3. Obtener acceso → SSH, credenciales, configuración
```

### Ficheros clave en Linux

| Fichero | Qué contiene |
|---------|--------------|
| `/etc/passwd` | Usuarios del sistema |
| `/home/usuario/.ssh/id_rsa` | Clave privada SSH |
| `config.php` | Credenciales de base de datos |
| `database.yml` | Configuración de DB |
| Ficheros de log | Credenciales en texto plano |

### Diccionarios para automatizar

```
SecLists/Fuzzing/LFI/
├── Linux/ ← rutas típicas de Linux
└── Windows/ ← rutas típicas de Windows
```

**Uso con Burp Intruder:**
1. Send to Intruder
2. Seleccionar el parámetro vulnerable
3. Cargar diccionario LFI de SecLists
4. Lanzar ataque (ajustar concurrencia a 1 request/seg en producción)

> [!important] El path traversal no es el fin
> El objetivo es escalar de leer `/etc/passwd` a obtener acceso al sistema: clave privada SSH, credenciales reutilizadas, o información de configuración que abra otra vía de entrada.

## ⑥ Checklist mental — Path Traversal

```
¿Veo un parámetro que sugiere nombre de archivo?
 │
 ├─ Probar ../ normal → Caso 1
 │
 ├─ Si bloquea ../ → probar ruta absoluta → Caso 2
 │
 ├─ Si elimina ../ → duplicar ....// → Caso 3
 │
 ├─ Si sigue bloqueando → URL encoding (%2e%2e%2f) → Caso 4
 │
 ├─ Si valida prefijo → incluir ruta + ../ → Caso 5
 │
 └─ Si valida extensión → null byte %00 + extensión → Caso 6
```

> [!tip] El razonamiento siempre es el mismo
> "¿Qué está validando el servidor? → ¿Cómo lo puedo bypassear? → ¿Qué no está contemplando el desarrollador?"

### Ruido y producción

| Contexto | Recomendación |
|----------|---------------|
| **Producción real** | Concurrencia baja (1 req/seg), no hacer fuerza bruta |
| **Examen/BSCP** | Se puede ser más agresivo |
| **Auditoría con cliente** | Preguntar qué tolerancia hay al ruido |

### Sistema operativo

| SO | Rutas típicas |
|----|---------------|
| **Linux** | `/etc/passwd`, `/etc/shadow`, `/home/` |
| **Windows** | `C:\Windows\System32\`, `C:\Users\` |

### Barras invertidas (Windows)

```powershell
# En Windows, la barra invertida también funciona:
..\..\..\..\etc\passwd

# O con URL encoding:
..%5c..%5c..%5c..%5cetc%5cpasswd
```
