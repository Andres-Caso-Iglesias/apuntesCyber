## ① La crisis de tokens — Septiembre 2026

| Concepto | Antes (julio) | Ahora (septiembre) |
|---|---|---|
| **Cuentas** | 1 cuenta compartida (200€) | 7 cuentas (200€ cada una) |
| **Duración** | 1 semana completa | 3-5 horas |
| **Límite semanal** | Infinito | 12 horas |
| **Coste mensual** | 200€ | 1.400€ |
| **Reducción tokens** | — | 50% menos (anunciado 15 sept) |

> [!warning] La demanda colectiva
> Antropic anunció una reducción del 50% de tokens. La gente se enfadó y montaron una demanda colectiva (1.5M personas). Antropic frenó la reducción, pero el daño ya está hecho.

### El "crash" de la IA civil

- El modelo de negocio no es sostenible
- Están en una carrera por ver quién llega primero a la superinteligencia
- Los usuarios civiles somos "el caramelito" para hacernos dependientes

## ② El modelo híbrido — Arquitecto + Obreros

### La metáfora del edificio

| Rol | Modelo | Función |
|---|---|---|
| **Arquitecto** | Claude (API) | Diseña planos, toma decisiones complejas |
| **Capataz** | Modelo local entrenado | Vigila a los obreros, aprende del arquitecto |
| **Obreros** | Kimi3, Qwen (locales) | Ejecutan tareas de codificación |

> [!important] La analogía
> "¿Para qué vamos a estar pagando a todos estos obreros como si fuesen arquitectos cuando podemos estar pagándolos como si fuesen obreros?"

### La apuesta por Apple Mac Studio

| Componente | Especificación |
|---|---|
| **Chip** | M5 Ultra |
| **SSD** | 2TB |
| **Memoria unificada** | 512GB |
| **Coste estimado** | ~12.000€/unidad |
| **Objetivo** | 10 Mac Studios = 5TB memoria unificada |

### Rentabilidad del modelo híbrido

```
4 Mac Studios = 48.000€
= 70 requests concurrentes
= 12 "trabajadores"
= Productividad x2 = 24 personas equivalentes
= 48.000€ / 24 = 2.000€/persona/año = 180€/mes
= Mismo coste que una suscripción a Claude Code
```

**Primer año:** Amortizar infraestructura
**Segundo año:** Beneficio puro (180€/mes por trabajador vs 2.000€/mes con Claude)

> [!tip] El 85% de reducción de costes
> En 3 meses: pasar de 70% a 85% de reducción usando API de Claude para razonamiento + modelos locales para ejecución.

## ③ El futuro de la IA — La visión de Carlos

### La carrera por la superinteligencia

| Empresa | Estrategia |
|---|---|
| **Anthropic** | Modelo civil: Opus 5 como tope. Privado: superinteligencia |
| **OpenAI** | GPT-6 Astra, modelos más potentes |
| **Google** | Gemini, I+D continuo |
| **Apple** | Hardware, no modelos. Soporte para modelos locales |
| **Chinos** | Kimi3, Qwen al 80% de Opus |

> [!important] Apple NO saca modelo de IA
> Apple se centró en hacer **hardware** (Mac Studio) que aloje modelos de IA. Mientras otros peleaban por modelos, Apple construyó la máquina.

### La IA privada vs la civil

```
IA Civil: Opus 5 → evolución calmada y progresiva
IA Privada (Defensa, grandes empresas): → superinteligencia
```

> [!warning] Los "frenos" son solo para civiles
> Cuando Antropic, OpenAI y Elon Musk dicen "vamos a frenar", se refieren a frenar el acceso público. La carrera militar/empresarial sigue a toda marcha.

## ④ Metodología de trabajo con IA — El orquestador

### Estructura de una IA según Carlos

```
cloud.md (System Prompt)
    ↓
Orquestador (selecciona modelo por tarea)
    ↓
┌─────────────┬─────────────┬─────────────┐
│   Haiku      │   Opus      │   Fable     │
│  (research)  │ (razonar)   │ (codificar) │
└─────────────┴─────────────┴─────────────┘
    ↓
Skills (bibliotecas .md)
    ↓
MCP Server (herramientas + skills)
```

### Selección de modelo por tarea

| Tarea | Modelo | Por qué |
|---|---|---|
| Research en internet | Haiku 4.5 | Barato, rápido, 24h corriendo |
| Organizar grafo | Opus 4.8 | Razonamiento complejo |
| Codificación | Kimi3/Qwen | Local, sin tokens |
| Revisión | Claude (API) | El más potente |

> [!tip] No usar un Fable para todo
> "La gente, como los tokens eran gratis, lo que estaba haciendo es agujeros a bombazos. ¡Boom! ¡Token! El consumo ha sido exponencial."

## ⑤ Notas de clase

- **La IA civil está en declive**: tokens más caros, menos capacidad
- **El modelo híbrido es el futuro**: API para razonamiento + local para ejecución
- **Apple apostó por hardware**, no por modelos
- **Los modelos locales evolucionan rápido**: Kimi3, Qwen ya al 80% de Opus
- **El orquestador es clave**: seleccionar el modelo adecuado para cada tarea
- **Las skills y los grafos de conocimiento** son lo que refina una IA
- **MCP Server** = taller mecánico (herramientas + skills)
- **Los juniors con IA son más productivos**, pero la demanda baja
