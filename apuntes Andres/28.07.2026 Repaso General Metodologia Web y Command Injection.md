## ① Repaso rápido — Laboratorio 1: búsquedas encadenadas

### Escenario

Portal con optionid que recibe parámetros del usuario para generar consultas SQL.

### Descubrimiento

| Hito | Detalle |
|---|---|
| Cambiar el valor del optionid | Select distinto en la SQL |
| Observar el tráfico | Petición en Query con `SELECT * FROM products WHERE optionid = [valor del usuario]` |
| Primer intento | `3 AND 1=1` → funciona |

### Payload de inyección SQL

```sql
3 AND 1=1
```

> [!important] La metáfora
> Es como si el.input del usuario entrara **sin comillas en la línea de la consulta**. Si el original es:
> `SELECT * FROM products WHERE id = [input]`
> Y tu input es `3 OR 1=1`, ejecuta:
> `SELECT * FROM products WHERE id = 3 OR 1=1`

## ② Repaso rápido — Laboratorio 2: User-Agent con retroalimentación

### Escenario

Otro portal. El parámetro de Name no se filtra pero sí se muestra en el output. El parámetro de Password no se muestra nunca.

### Flujo de detección

| Paso | Acción | Resultado |
|---|---|---|
| Probar el input name | `7*7` | Aparece `7*7` pero no `49` |
| Probar con parentesis | `7*(7+7)` | Aparece `7*(7+7)` pero no `98` |
| Intento de SQL Injection | `7*(7+7) OR 1=1` | No cambia nada |
| Probar User-Agent | `7*(7+7)` | Cambia el input pero no hace nada |

### Conclusión

El input name es **inyectado directamente en la query**, mientras que el User-Agent es **reflejado en el output** pero no se inyecta en la consulta.

> [!important] La idea clave
> En SQL Injection, **el valor que tu introduces se pone directamente en la query**. El User-Agent no se ejecuta, solo se muestra en la pantalla.

## ③ Command Injection desde cero

### Qué es

Una vulnerabilidad que permite al atacante **ejecutar comandos del sistema operativo** desde una aplicación web.

### Diferencia fundamental con SSTI

| Técnica | Qué inyecta | Dónde se ejecuta |
|---|---|---|
| **SSTI** | Plantilla (código de lenguaje) | Motor de plantillas |
| **Command Injection** | Comando del sistema operativo | Terminal del servidor |

### Ejemplo conceptual

Si una web tiene un campo que ejecuta un ping:

```bash
ping [input]
```

Y el input es `; whoami`, el servidor ejecuta:

```bash
ping ; whoami
```

El punto y coma concatena comandos en la terminal.

## ④ Hydra — Fuerza bruta contra SSH

### Instalación

```bash
sudo apt update && sudo apt install -y hydra
```

### Sintaxis básica

```bash
hydra -l [usuario] -P [wordlist] -t [hilos] [IP del servidor] [protocolo]
```

| Flag | Significado |
|---|---|
| `-l` | Login (usuario conocido) |
| `-L` | Lista de usuarios (si no se conoce el usuario) |
| `-p` | Password conocido |
| `-P` | Lista de passwords (wordlist) |
| `-t` | Número de hilos (peticiones simultáneas) |
| `-f` | Para al encontrar la primera combinación válida |
| `ssh://` | Protocolo a atacar |

### Ejemplo práctico

```bash
# Ataque contra SSH del labour 2
hydra -l mitch -P /usr/share/wordlists/rockyou.txt -t 4 ssh://178.62.197.94:2222

# Resultado: mitch:secret123
```

> [!important] La idea clave
> Hydra no es magia. Es una herramienta de **fuerza bruta** que prueba combinaciones una por una a alta velocidad. Su eficacia depende de la wordlist y de la política de bloqueo del servidor.

### Diferencia entre hydra y Burp

| Herramienta | Uso principal | Protocolos |
|---|---|---|
| **Burp Suite** | Auditoría web (HTTP) | HTTP/HTTPS |
| **Hydra** | Fuerza bruta en servicios | SSH, FTP, RDP, HTTP, etc. |
