# 09.06.2026 — Escalada de Privilegios y Hacking Web: Máquina Ridiculously Easy II y Mr. Robot

## Resumen

Segunda parte de la máquina Ridiculously Easy. Se completó la escalada de privilegios desde una cuenta de servicio hasta root, pasando por movimiento lateral entre usuarios. Se explicaron los conceptos de tipos de usuarios en Linux, permisos, y uso de SCP para transferencia de ficheros.

---

## Tipos de Usuarios en Linux

### Cuentas de Servicio
- Creadas por servicios (SSH, FTP, HTTP)
- Tienen permisos muy reducidos sobre el sistema
- **No tienen `/home` propio**
- Ejemplo: `www-data`, `ftp`, `apache`
- Al comprometer una web, normalmente obtenemos una shell como `www-data`

### Cuentas de Sistema
- Usuarios creados para administración
- **Sí tienen `/home` propio** (barra home)
- Pueden tener shell interactiva
- Ejemplo: `summer`, `morty`, `rick_sanchez`

### Cuentas Admin (root)
- Acceso total al sistema
- No tiene `/home` — tiene `/root` (el palacio)
- Se accede con `sudo su` o `su -`

```
Compromiso inicial (cuenta de servicio: www-data)
    ↓
Movimiento lateral (pasar a cuenta de usuario)
```

## Enumeración Interna

### Ver usuarios del sistema
```bash
cat /etc/passwd
```
- Cada línea es un usuario
- Si tiene `/bin/bash` o `/bin/sh` → tiene shell interactiva
- Si tiene `/home/` → es usuario de sistema accedible por SSH

### Ver permisos de sudo
```bash
sudo -l
```
- Lista los comandos que podemos ejecutar como root sin contraseña
- Si dice `(ALL : ALL) ALL` → podemos ejecutar TODO como root

### Buscar ficheros SUID
```bash
find / -perm -4000 2>/dev/null
```
- Ficheros con permiso SUID se ejecutan como el propietario (normalmente root)
- Importante para escalada de privilegios

---

## Permisos en Linux

### Estructura
```
-rwxrwxrwx
 │││││││││
 ││││││└┴┴── Others (otros usuarios)
 │││└┴┴──── Group (grupo)
 └┴┴─────── Owner (propietario)
```

### Permisos
- **r** (read) = 4 → Lectura
- **w** (write) = 2 → Escritura
- **x** (execute) = 1 → Ejecución

### Regla para copiar ficheros
- **Fuente** → debe tener permiso de **lectura** (r)
- **Destino** → debe tener permiso de **escritura** (w)
- No necesitas lectura en el destino, solo escritura

---

## SCP — Copia de Ficheros por SSH

### Sintaxis
```bash
scp usuario@ip:/ruta/fichero /destino/local/
```

### Ejemplo
```bash
scp summer@10.0.2.15:/home/summer/safe.txt ./Desktop/
```

### Si el puerto SSH no es el 22
```bash
scp -P 2222 summer@10.0.2.15:/home/summer/safe.txt ./
```

### Subir ficheros a la máquina víctima
```bash
scp malware.sh summer@10.0.2.15:/tmp/
```

---

## Directorio /tmp

- Es un directorio temporal con permisos de **escritura** para todos
- Se usa para subir y ejecutar malware durante un ataque
- **Se borra en cada reinicio** → no queda rastro
- Color diferente en `ls` por los permisos especiales ( Sticky Bit)

## Escalada de Privilegios en Ridiculously Easy

### Proceso seguido

1. **Obtener shell como usuario** (Summer) mediante SSH con contraseña `Winter`
2. **Enumerar sistema**: `sudo -l`, `find / -perm -4000`, revisar `/etc/passwd`
3. **Investigar ficheros** en home de otros usuarios (Rick Sánchez, Morty)
4. **Encontrar pista**: imagen JPG con contraseña oculta en metadatos (`strings safe_password.jpg`)
5. **Descifrar**: ejecutable `safe` que necesita un argumento → usar la contraseña encontrada
6. **Obtener pista de root**: "una mayúscula + un dígito + nombre de banda"
7. **Generar diccionario** con esas reglas
8. **Fuerza bruta con Hydra** contra SSH de Rick Sánchez
9. **Acceder como Rick**: `sudo -l` muestra que puede ejecutar TODO como root
10. **Escalar**: `sudo su` → root → `cat /root/root.txt`

### Comandos clave utilizados
```bash
# Ver permisos de sudo
sudo -l

# Copiar fichero con SCP
scp -P 2222 summer@10.0.2.15:/home/rick_sanchez/safe.txt ./

# Ver strings de un fichero
strings safe.txt

# Fuerza bruta con Hydra
hydra -L users.txt -P diccionario.txt ssh://10.0.2.15:2222

# Escalar a root (cuando sudo -l da ALL)
sudo su
```

---

## Hydra — Fuerza Bruta

### Sintaxis
```bash
hydra -l usuario -P diccionario.txt ssh://ip:puerto
```

### Parámetros
- `-l` → usuario específico
- `-L` → archivo de usuarios
- `-p` → contraseña específica
- `-P` → archivo de contraseñas
- `ssh://` → protocolo a atacar

---

## Puntos Clave

- Siempre hacer `sudo -l` al entrar en una máquina — puede ser la escalada directa
- `strings` extrae texto legible de cualquier fichero (imágenes, binarios, etc.)
- SCP necesita que el puerto SSH esté abierto y tengas credenciales válidas
- El directorio `/tmp` es tu mejor amigo para subir herramientas
- Nunca descartes un fichero sin investigarlo — la pista puede estar en metadatos
- Un CTF no es una auditoría real, pero enseña la metodología
